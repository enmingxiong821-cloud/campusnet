## 第一部分 · 结论与优先级

### 1.1 一句话总结

本项目在**认证协议层**已领先同类（多厂商声明式规则 + UTF-16 码元的 xxtea 比 Go/Rust 实现对中文更稳 + `auth_state` 三分判断），
**真正的短板集中在三处**：① 自启的「无人登录」语义没落地；② 登录失败没有分类熔断（有锁号风险）；
③ 远程电源只做完了「关」，且插件那条已被宣称的链路实际是断的。

### 1.2 行动清单（按性价比排序）

| # | 要做的事 | 依据 | 材料位置 | 成本 | 收益 |
|---|---|---|---|---|---|
| 1 | 修插件 `POST /api/check` 403：**携带有效令牌时跳过同源校验** | 实测 403 + `w3c/webextensions#777`（GET 不带 Origin、非 GET 必带）+ OWASP「自定义请求头」防御 | E §0–2 | 极低（服务端 1 处 + 扩展加 1 头） | 兑现既有宣称，消除静默降级 |
| 2 | 本机自启切 `--mode task`（开机触发、无需登录） | 本机 `doctor` 实测仍是「登录后」语义 | D §1–3 | 极低（一条命令，需管理员） | 直接兑现「有电就连」 |
| 3 | **登录失败分类熔断**：密码错判终态、不重试 | Campus-Auth `AttemptOutcomeType.INVALID_CREDENTIAL`；本站现状 3 分钟内可能提交约 36 次 | B §1–2、§「对本项目的改法」1 | 低 | 消除锁号风险（当前最大可靠性隐患） |
| 4 | 退避曲线改指数 + 上限 + 抖动 | BitSrunLoginGo `initial=2s / ×2 / max=300s` | B §1、§「可照抄的参数对照表」 | 低 | 断网/门户故障时不刷屏 |
| 5 | 探活/登录前**预检**：网卡物理断开、认证地址 TCP 不可达 → 跳过提交 | Campus-Auth `check_login_prerequisites` | B §2 | 低 | 减少无谓尝试与日志噪音 |
| 6 | 单实例锁改内核锁（`flock` / `CreateMutexW`） | systemd 官方「PID files should be avoided」；现实现有 TOCTOU | D §2(f) | 低 | 消除双实例写同一 SQLite |
| 7 | 补 Linux `loginctl enable-linger`、macOS 改 **LaunchDaemon** | LaunchAgent 的 `RunAtLoad` 只在登录时跑 | D §1–3 | 中 | 跨平台「无人登录」才成立 |
| 8 | 远程关机加**可撤销窗口**（延迟 + `shutdown /a`）+ 冷却 + 审计 | bmc-adapters 的 graceful 绝不下沉硬断电；Windows `shutdown /a` | C §2–3 | 中 | 破坏性操作变得可挽回 |
| 9 | `doctor` / `power guide` 自动检测「本机能否远程开机」 | `powercfg /devicequery wake_armed`、`Get-NetAdapterPowerManagement`、`HiberbootEnabled` | C §4、§6 | 中 | 把硬件前提变成可执行检查，不再靠文档讲道理 |
| 10 | 协议层三条自愈：`client_ip` 回填、`enc` 自动探测、免凭据判在线 | zu1k/srun `detect_ip`；BitSrunLoginGo `DetectEnc`、`Reality()` | A §五 1–3 | 中 | 门户改版/IP 配错时不再 `sign_error` |
| 11 | PWA 化（**前提：需 HTTPS，用 Tailscale Serve**） | SW 仅安全上下文可注册，`http://192.168.x.x` 不行 | E §3 | 中 | 「多端」性价比最高的一块 |
| 12 | 规则 schema 落 `schema_version` + 严格白名单校验；`profiles update` 走「sha256 清单 + 原子替换回滚」 | sing-box rule-set 的「先验后提交」；规则**永不进解释器**才是防 RCE 的关键 | F §1–2 | 中高 | 通用性天花板与供应链安全 |
| 13 | 收敛凭据外发面：表单 action 主机白名单、探活跳转 scheme 白名单 | 审查发现（`portal.py:435`、`probe.py:163`） | 见审查报告 | 低 | 堵住凭据外泄与本地文件读取 |

### 1.3 与本项目既有判断的对照（哪些被证实、哪些要修正）

| 我此前的判断 | 材料给出的结论 | 状态 |
|---|---|---|
| 插件 403 导致「交给本地服务」从未生效 | `w3c/webextensions#777` 给出规范层依据，并给出 OWASP 背书的修法 | **证实**，且拿到了权威出处 |
| 「monitor 无长程退避」是缺陷 | 对重连守护，固定 60s 是对的；**真正的病是缺失败分类** | **修正**：不要把退避当主问题 |
| Cookie 缺 `Secure` 是漏洞 | 明文 HTTP 下加 `Secure` 会直接废掉登录；真问题是局域网明文 + 可远程关机 | **修正**表述 |
| PWA 是多端性价比最高的一步 | 方向对，但**必须补前提**：内网 HTTP 下 SW 注册不了、Chrome 不允许安装 | **补充前提** |
| 远程开机软件做不到 | 仍是硬约束，但**可自动检测**条件（`powercfg` 等），能做成向导 | **加强**：从「说明」升级为「检测」 |
| Tailscale 正在内建 WoL | 假消息，issue #14573 已于 2025-01-08 `Closed as not planned` | **证伪**，已从材料中剔除 |

## A-认证协议与多厂商适配（源码级调研）

结论先行：多厂商适配只有两条路——**声明式配置**（改 config 不动代码，Dr.COM/zu1k-srun 系）与**协议+探测**（硬编码单一协议但自动探测门户参数，BitSrunLoginGo）。本站项目走的是更进一步的「profile JSON 声明 + 少量协议实现」，覆盖面最广；可借鉴点是 **自动探测（enc/ip/acid）** 与 **challenge 回包回填 IP**。

### 一、SRUN 系

| 项目 | 语言/★/最后提交 | 怎么抽象一所学校 | IP 探测 | 会话复核 |
|---|---|---|---|---|
| [Mmx233/BitSrunLoginGo](https://github.com/Mmx233/BitSrunLoginGo) | Go / 566 / 2026-09-20 | 单协议硬编码 + `LoginMeta{N,Type,Acid,Enc,OS,Name,InfoPrefix,DoubleStack}` 可配；`Detector` 自动探测 acid/enc/ip | 正则抓登录页 `ip:"…"` | `LoginStatus` 查 `rad_user_info`，认 `error=="ok"` |

| [cesaryuan/srun](https://github.com/cesaryuan/srun) | Rust(fork)/0 / — | 同 zu1k | 同 zu1k，且 `get_token` 把 challenge 回包 `client_ip` 写回 `self.ip` | 同 zu1k |
| [coffeehat/BIT-srun-login-script](https://github.com/coffeehat/BIT-srun-login-script) | Py / 223 / 2024-04-19 | 改 `LoginManager(...)` 构造参数（URL/acid/enc/n） | 正则抓登录页 `id="user_ip" value="…"` | 正则取 `suc_msg` |

源码要点：
- 加密链一致：`hmd5=HMAC-MD5(token,pwd)`；`info="{SRBX1}"+换表Base64(xxtea(json))`；`chksum=SHA1(token+user+token+md5+token+acid+token+ip+token+n+token+type+token+info)`。BitSrunLoginGo `pkg/srun/srun.go:117`、zu1k `src/xencode.rs:79`、BIT `LoginManager.py:127`。
- xxtea 轮数均为 `floor(6+52/(n+1))`；BitSrunLoginGo 用常量 `c=0x86014019|0x183639A0`（=`0x9E3779B9`），`XEncode.go:49`。
- **码元差异**：本站按 UTF-16 码元打包（同 Portal.js `charCodeAt`），Go/Rust/Py 各实现都用 **UTF-8 字节**（`ordat` / `msg.as_bytes()` / `ord()`）——纯 ASCII 等价，本站对中文更稳（`ensure_ascii=True`）。
- 小怪癖：BitSrunLoginGo `pkg/srun/encode.go:26` Sha1 返回 `"%x\n"`（带换行）。

## C · 远程电源控制（源码级调研）

目标场景：宿舍里的 Windows 台式机/笔记本，「有电就自动联网 + 远程开关机」。

### 一、值得抄的抽象：把「电源动作」建模成动词，而非布尔

`KVMFleet/bmc-adapters`（Apache-2.0）是最好的模板，源自 `bmc-toolbox/bmclib`：

- `bmc_adapters/base.py`：`Feature`（StrEnum，含 `POWER_STATE`/`POWER_SET`/`WAKE`）+ `FeatureProvider`(Protocol) + `BMCAdapter`(ABC)。每个适配器**声明自己支持哪些 feature**，未实现默认 `NotImplementedError` —— 「不支持」是显式失败，不是静默降级。
- `bmc_adapters/bmc.py` 的 `BMC` 编排器按 **Redfish → IPMI → PDU** 顺序 dispatch，返回**实际处理它的传输名**。
- 动词表（`redfish/client.py` / `ipmi/types.py`）：`on / off(GracefulShutdown) / off_hard(ForceOff) / cycle(ForceRestart) / reboot(GracefulRestart)`；IPMI 多一个 `soft`。
- **最该抄的安全点**：`BMC._PDU_SERVICEABLE` 规定 graceful 动作（reboot/off）**绝不下沉到 PDU 硬断电**，否则一次 reboot 变成 mains 断电、损坏文件系统 —— 无 in-band 传输可服务时直接 `raise`。
- 电源状态统一为字符串 `"On"/"Off"/"PoweringOn"/"PoweringOff"`，`None` 表示无信号（≠ 0）。

**Home Assistant `/wake_on_lan`**：switch 的 `turn_on()` = 发魔术包（`wakeonlan.send_magic_packet`）；`turn_off()` = 跑用户配置的 `turn_off` script（SSH/agent 关机，不硬编码）。有 `host` 时 `should_poll=True` 用 `ping -c1 -W1` 上报真实状态，否则 `assumed_state=True`。

**UpSnap**（Go）：`wake.go` 发完包后**轮询 ping 直到在线或 `wake_timeout`(默认 120s) 超时**，超时返回明确错误；`magicpacket.go` 跨网段时同发**广播地址:9/:7 与单播 deviceIP:9/:7**。

**MeshCentral Intel AMT**（`amtmanager.js`）：`RequestPowerStateChange(action)`，动作码 `2=Power up,5=Cycle,8=Off,10=Reset,11–16=带 BIOS/PXE 的加电或重启`；**AMT 10+ 唤醒后再补发 `RequestOSPowerStateChange(2)`** 以拉起 Modern Standby；状态经 `powerConversionTable` 归一化。

### 二、电源动作接口设计建议（可照抄）

```python
# power.py 建议扩展；沿用现有 PowerError / _run 风格
from dataclasses import dataclass

ACTIONS = ("status", "on", "off", "off_hard", "reboot", "cycle")  # 动词化，非布尔

@dataclass
class PowerResult:
    ok: bool
    action: str
    transport: str | None   # "system" | "wol" | "amt" | "pdu" | None
    state: str | None       # "on" | "off" | "unknown"
    supported: bool = True  # False = 本机没有这条路径（显式"不支持"，不抛异常）
    detail: str = ""

def power_capabilities() -> dict:            # {wol: bool, amt: bool, pdu: bool, fast_startup: bool}
    ...
def power_status(*, target="local", timeout=5) -> str:      # "on"/"off"/"unknown"
def power_action(action, *, target="local", delay=30,
                 dry_run=False, abort_window=True) -> PowerResult:  # on 只能走 wol/amt/pdu
    ...
def abort_shutdown() -> PowerResult:         # Windows: shutdown /a  ← 可撤销
    ...
```
约定：`off`=优雅（绝不静默硬断电，抄 bmc-adapters）；`off_hard`=立即；`on` 仅 `wol/amt/pdu` 支持，否则 `supported=False`；**幂等**——已处于目标态则 no-op 返回 `state`；超时：本机关机命令 15s、`on` 轮询 ≈120s（抄 UpSnap）；动作字符串非法 → `PowerError`。

### 三、安全：破坏性操作的真实范式

- 本项目现状缺陷已确认：`shutdown /t 0` 不可撤销、无冷却、`confirm` 仅布尔、无审计。
- **可撤销窗口**：Windows 原生 `shutdown /s /t <秒>` 后可用 **`shutdown /a`** 中止（[MS Docs](https://learn.microsoft.com/zh-cn/windows-server/administration/windows-commands/shutdown)）。建议 `delay` 默认 30–60s，并提供 `/api/power/abort`。
- **冷却/超时**：抄 UpSnap 的 `wake_timeout`；唤醒请求应串行化并有「操作中」状态。
- **审计**：抄 bmc-adapters 的 `findings` 列表与 MeshCentral power events；本项目已有 `stage="power"` 日志，补 `action/target/result/transport` 字段即可。
- **二次确认**：HA 把「关机」交给用户自定义 script，不做隐式破坏。

### 四、WOL 硬约束 + Windows 可执行检测

**必然无效的条件**：跨三层（除非路由器开 subnet-directed broadcast / `ip directed-broadcast`）；Wi‑Fi（多数网卡断电即不再收包，仅少数 WoWLAN）；Windows **Fast Startup** 让内核休眠、网卡断电；BIOS/驱动「魔术包唤醒 / 待机供电」未开；校园网 AP/交换机的 **client isolation** 或广播过滤丢包。

**检测命令（可直接进 doctor）**：
- `powercfg /devicequery wake_armed`（已授权可唤醒的设备）、`wake_programmable`、`powercfg /a`（S3 可用性）。
- `Get-NetAdapterPowerManagement -Name <nic>` → `WakeOnMagicPacket` 是否 `Enabled`。
- 关 Fast Startup：`powercfg /h off`，或注册表 `HiberbootEnabled=0`（[powercfg 选项](https://learn.microsoft.com/zh-cn/windows-hardware/design/device-experiences/powercfg-command-line-options)）。

| 平台 | 载体 | 需登录? | 权限 | 卸载要清 | 关键命令/API | 常见失败 |
|---|---|---|---|---|---|---|

| Win | 计划任务 ONSTART | **否** | 注册需管理员 | `schtasks /Delete /TN` | `Register-ScheduledTask -Trigger (New-ScheduledTaskTrigger -AtStartup) -User <acct> -Password <sec>` | 存入 LSA 凭据被拒=非管理员；空密码账户无法存 |
| Win | 服务(sc.exe/NSSM/WinSW) | **否** | 管理员 | `sc delete` | `CreateService`；NSSM/WinSW 包一层 | Session0 无 UI；交互被禁 |
| Linux | systemd **user**+linger | **否** | 自身可 enable-linger | `disable-linger`+删 unit | `systemctl --user enable` + `loginctl enable-linger $USER` | 不 linger 则登出即停 |

### 2. 六个缺陷的确定修法

**(a) Linux linger**：`systemctl --user enable --now` 后补 `loginctl enable-linger $USER`（等价写 `/var/lib/systemd/linger/<user>`）；卸载 `loginctl disable-linger`。官方原文：linger 后"a user manager is spawned… at boot and kept around after logouts"，这才是无人登录前提。

**(b) macOS 生效**：写 plist 后必须 `launchctl bootstrap gui/$(id -u) <plist>`（agent）/`bootstrap system <plist>`（daemon）；卸载先 `launchctl bootout <域> <plist>` 再删文件。参考 `Campus-Auth/app/services/autostart.py:215` 与 `meshcentral/macosinstaller.js:84-91`（`bootout`→`bootstrap`，失败回退 `load`）。

**(c) 提权判定**：勿匹配英文串。注册前用 `[Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()|%{IsInRole("Administrator")}` 预判，或捕获异常的 `HRESULT 0x80070005`/`$_.Exception`，别依赖 `access is denied`。

**(d) .cmd 引号**：不要按"含空格"手工加引号。首选用 `subprocess.list2cmdline(launch_command(...))`（本项目 CLI 已依赖它）；但 `%` 在 cmd 中恒展开、无解——Windows 应首选计划任务（`-Execute` 直传 exe 不经 shell），退路改 .vbs（`Campus-Auth` 即用 VBS，并在含 CJK 路径时拒绝）。

**(e) 双载体**：`install()` 定 mode 前先清另一载体——task 先删启动文件夹 .cmd，auto 先 `delete_task()`；`status()` 需同时报告两种。已有 `uninstall()` 清 Linux 两载体的先例可复用。

**(f) 单实例**：弃 PID 文件，改内核级锁——POSIX `fcntl.flock(fd, LOCK_EX|LOCK_NB)`；Windows `CreateMutexW("Global\\campusnet")` 判 `ERROR_ALREADY_EXISTS`。进程死锁即释放，无残留判定、无 TOCTOU。参见 `filelock/src/filelock/_unix.py:50`、`_windows.py:162`（`LockFileEx`）。若保留 PID 文件：`_unix.py:61` 注释明确"release 后不 unlink"以免 inode 分裂；当前代码"判残留后无条件 unlink"正是竞态源。

### 3. "一通电就联网"能做到吗

- **Win**：能。计划任务 ONSTART + `-LogonType Password`(存 LSA) 或 `S4U`（不存密码但无网络凭据）。做不到：空密码账户、非管理员拒存凭据、只用启动文件夹。
- **Linux**：能，前提 systemd **且** 已 `enable-linger`。做不到：容器瘦镜像/旧版无 systemd、WSL 未开 systemd。
- **macOS**：能，但必须 **LaunchDaemon**（/Library/LaunchDaemons，root）。LaunchAgent 做不到——gui 域须有图形会话，RunAtLoad 在登录时执行。

### 4. 常见坑

- .cmd 首行 `chcp 65001` 且文件存 UTF-8；PowerShell 脚本存 UTF-8 BOM 或用 `-EncodedCommand`，否则中文乱码。
- macOS TCC/Automation 授权在无 UI 的 daemon 里无法弹窗，需预授权。
- Windows「快速启动」下"关机"实为休眠，ONSTART 不触发；用 `-StartWhenAvailable` 缓解，或改 ONLOGON/唤醒触发。
- systemd/launchd 环境干净，不继承用户代理；需在 unit/plist 显式 `Environment=`。Python `urllib` 会读 `HTTP(S)_PROXY`。

## E · 多端形态与远程访问（源码级资料汇编）

### 0. 403 根因与确定修法

**根因（读本项目源码）**：`project/backend/campusnet/server.py:725-745` 的 `require_same_origin()` 在请求带 `Origin` 时要求 `urlsplit(origin).netloc == Host`。扩展 SW 的 `POST /api/check`（`extension/background.js:226-231`）带 `Origin: chrome-extension://<id>`，netloc=`<id>` ≠ `127.0.0.1:2268` → 必然 403。

**权威依据**：`w3c/webextensions#777` 确认——被 `host_permissions` 覆盖的请求中，GET/HEAD **不带** `Origin`，而 **POST/PUT/PATCH/DELETE 会带**，值即扩展来源 `chrome-extension://<id>`（浏览器设定，页面无法伪造）。Fetch Metadata 规范 §4.4：扩展对目标 URL 有权限时 `Sec-Fetch-Site` **可能是 `same-origin`**，无权限则 `cross-site`；`Origin` 值"实现定义"。即：本例 `Origin` 非空且非本站，现逻辑必拒。

**推荐：(a) 携带有效显式令牌即跳过同源校验**，可叠加 (b) 把来源收窄到确切扩展 ID。改法：`_dispatch` 里先算 `token_ok = auth.authenticated(headers)`，透传给 `require_same_origin` 作豁免；扩展在 options 存令牌，给 `/api/check` 加头 `X-CampusNet-Token`（`host_permissions: http://*/*` 已覆盖回环，不触发预检）。

### 1. 扩展↔本地服务通信：方案对比与推荐

| 方案 | 安全性 | 实现成本 | 权威依据 |
|---|---|---|---|
| **(a) 有效 Bearer/自定义头 → 跳过同源** | 高：令牌非浏览器自动附带，跨站页读不到、设该头会预检且服务端不放行 | 低（服务端 1 处 + 扩展加 1 头 + 存令牌） | OWASP CSRF Cheat Sheet（自定义请求头防御，CORS 预检为据）；本项目 `auth.authenticated` 已支持 `Authorization: Bearer` 与 `X-CampusNet-Token` |
| **(b) `Origin: chrome-extension://<固定ID>` 白名单** | 中：`Origin` 由浏览器设定不可伪造，可作信号；但单靠它=按来源放行、无凭据 | 中（需在 manifest 固定扩展 key，否则未打包 ID 会变） | `career-ops#3597`（默认空、显式开启、拒绝 `null`、Host 校验独立）；Fetch Metadata §4.4 |
| **(c) Native Messaging** | 最高：进程间 stdio、无端口、`allowed_origins` 无通配 | 高：Win 注册表 + host manifest，Mac/Linux 固定目录；与"单文件 EXE/纯标准库"定位冲突，且失去远程/浏览器无关性 | Chrome 官方 native-messaging；Bitwarden IPC、KeePassXC-Browser 均用它（常驻桌面客户端） |
| **(d) 其它（自定义头 + 令牌 / 反代同源）** | 同 (a)（本质等价） | 低 | 同 (a) |

**结论**：(a) 为主，安全且低成本；(b) 仅作纵深加固（把浏览器来源再收窄到确切 ID）；(c) 对本项目分发成本过高，不划算。切勿回 `Access-Control-Allow-Origin: *`，否则 (a) 失效。

### 2. CSRF 与令牌的正确组合

OWASP CSRF Cheat Sheet 认可"自定义请求头"防御，依据是浏览器对自定义头强制 CORS 预检，跨站无法静默发出。安全根本：令牌**不被浏览器自动附带**、跨站 JS 既读不到也设不上（`Authorization` 同理）。**不能放行**：令牌存 Cookie（自动附带=回到 CSRF）、令牌进 URL/GET、CORS 通配、任意 XSS（"XSS 可绕过一切 CSRF 防御"）。故豁免必须是"**校验令牌有效，而非仅存在**"。

**第十轮（2026-10-14）落地与两条更正**：

1. **只挡写请求不够——有副作用的 GET 同样能被打**。`/api/probe`、`/api/discover`、`/api/detect-portal` 会扫网段连端口，`/api/doctor/power` 会跑 `powercfg` / PowerShell，而它们都是 GET：`<img src="http://127.0.0.1:2268/api/discover">` 就能触发。响应被同源策略挡着、服务也不发 CORS 头，页面**读不到**——但它不必读到也能驱动本机动手，这正是 OWASP 归在 CSRF 名下的「有副作用的 GET」/盲打（blind）形态。**终态**：GET 与写请求走同一道 `require_same_origin`，只白名单放行三条无副作用的 `/healthz`、`/api/health`、`/api/auth/status`（Docker `HEALTHCHECK`、扩展存活探测、控制台启动前的「服务起来了没」都要走它们，且扩展那几条会带 `Sec-Fetch-Site: cross-site`，一刀切会把正常链路一起挡掉）。
2. **上表 (b)「按扩展 ID 白名单」的收益被推翻**，理由不在 (b) 本身而在前提：本机任何进程本来就能不带 `Origin`、不带令牌直连 `127.0.0.1:2268`，**卡扩展 ID 挡不住任何真实攻击者**——它只在「攻击者能让你在浏览器里装上他的扩展」这一假设下才有意义，而那时他早已能直接连本机端口。徒增开发期加载未打包扩展的麻烦。已在 `require_same_origin` 的注释里写明，免得下轮审查重复提。
3. `Sec-Fetch-Site == "cross-site"` 在**没有 `Origin`** 的请求上也会单独触发拒绝（`server.py` 的 `require_same_origin`），这是一条与上表正交的防线：不依赖客户端行为，直接读浏览器给的元数据。


### 3. PWA 最小改造清单

- **新增 `manifest.json`**（必填）：`name` 或 `short_name`、`icons`（含 192 与 512 px）、`start_url`、`display: "standalone"`、`prefer_related_applications: false`。Chrome 现**不再强制 SW 才能安装**（install-criteria 未列 SW）。
- **新增 `sw.js`**：缓存 app shell。策略——静态资源 cache-first（precache `index.html`+图标），`/api/*` network-first 且不落缓存。
- **改 `index.html` `<head>`**：`<link rel="manifest" href="/manifest.json">`、`<meta name="theme-color">`、`<link rel="apple-touch-icon" href="icon180.png">`。
- 可照抄示例：`mdn/pwa-examples`、`GoogleChrome/samples`（verified）。
- **内网 HTTP 的限制与绕法**：Service Worker 仅能在安全上下文注册——HTTPS 或 `localhost`/`127.0.0.1`（MDN Secure Contexts）。在 `http://192.168.x.x` 下 **SW 无法注册 → 无离线**，且 Chrome 安装要求 HTTPS。绕法：① **Tailscale Serve** 自动签发 HTTPS 证书给 tailnet 内地址（首选，一举两得）；② `mkcert` 自签 + 反代（有告警）；③ Cloudflare Tunnel（公网 HTTPS）。
- **iOS 差异**：仅 Safari 可"加到主屏"（16.4+ 其它浏览器亦可）；无 `beforeinstallprompt`，靠 `display:standalone` 控制全屏外观。

### 4. 远程访问（校园网现实可行性）

共同点：均**免公网 IP、免入站端口**（frp 除外），PC 仅出站；**但都要求先有出站互联网，认证门户前隧道无法建立**（Tailscale 官方 captive-portals 明确）。

| 方案 | 需公网IP/开端口 | 校园 NAT/门户表现 | 合规/依赖 |
|---|---|---|---|
| Tailscale | 否/否 | NAT 穿透 ~90%+，失败回落 DERP(443) | 需账号；可自建 Headscale |
| ZeroTier | 否/否 | 直连失败经官方根中继；UDP 9993 易被封 | 需账号，官方控制器 |
| Cloudflare Tunnel | 否/否 | 出站 443 似 HTTPS，DPI 最易放行 | 完整隧道需账号+域名 |
| frp | **是/是**（frps 需公网+开 7000） | 协议特征明显，校园 DPI 易识别 | 校园封号/拉黑案例（appinn） |
| ngrok | 否/否 | 出站 443，CGNAT 可用 | 需账号+authtoken，强第三方；免费限流 |

**校园红线**：多数校园明文禁止私自内网穿透，仅放行 80/443；违规可断网/处分。**建议优先出站 443 且流量近似 HTTPS 者（Tailscale、Cloudflare Tunnel），避开 frp**，使用前报备网络中心。

### 5. 移动端壳 与 多端一致性（要点）

- **移动端壳**：Capacitor 最省（web `dist/` 丢入即用，Ionic 生产案例）；Tauri 2 更小（<600KB）但需 Rust/移动 SDK；React Native 是原生渲染器，包页面只能靠 WebView，**不适合**。
- **防漂移**：① 检测/认证**只留服务端**（本项目已做）；② 从 OpenAPI **生成客户端**（`openapi-generator`、`openapi-typescript`），各端皆薄客户端；③ CI 加 **codegen + OpenAPI diff 门禁**。参考：`stripe/openapi`、`fastapi/full-stack-fastapi-template`。

### 6. 多端路线图（按性价比排序）

1. **修 403**（扩展真正走本地服务）— 收益高/成本极低，立刻兑现既有宣称。
2. **PWA 化 + Tailscale Serve 供 HTTPS** — "多端"性价比最高：一套代码得手机主屏 App + 离线 + 远程 HTTPS。
3. **从 OpenAPI 生成共享 TS 客户端 + CI diff 门禁** — 根治多端漂移。
4. **远程访问**：优先 Tailscale（+Serve），次选 Cloudflare Tunnel；避开 frp。
5. （可选）**Capacitor 壳**打包成商店 App — 收益有限，最后做。

## F. 规则/插件化与「从远端拉规则」的信任模型

> 结论：本项目「规则=纯声明式 JSON」的方向与 Tasmota template、sing-box rule-set 一致，是对的。
> 补三样即闭环：**显式 version、白名单 schema 严格校验、签名+原子替换的可回滚更新**。
> 防「远端更新=RCE」靠的**不是签名**——签名只防篡改；**规则永不进解释器 + schema 白名单**才防代码。

### 1. 规则 schema 建议

抄谁：字段分层抄 **Home Assistant manifest**（必填/可选；custom 集成必带 `version`，core 不带）；
数字 `version`+迁移函数抄 **sing-box rule-set**（`RuleSetVersion1..5`+`Upgrade()`+`schema:"omit"` 弃用字段）；
「纯数据描述、无代码」抄 **Tasmota template**；匹配条件粒度抄 **mihomo rule-provider**（behavior 定格式）。

| 字段 | 类型 | 必填/默认 | 说明 |
|---|---|---|---|
| schema_version | int | ★ =1 | 程序认识的最大版本 |
| id | str `[a-z0-9-]{1,32}` | ★ | 唯一；同 id 用户覆盖内置 |
| name | str ≤60 | ★ | |
| priority | int 0–999 | 100 | 越大越先匹配（取代文件名前缀） |
| match.url_contains / body_contains | [str] ≤8 | [] | 命中计分 |
| match.hidden_fields / requires_form | [str]/bool | []/false | 隐藏域、必含表单 |
| login_mode | enum | browser | browser/http/srun/manual |
| password_mode | enum | plain | plain/base64/md5/md5_base64/sha256 |
| username_fields / password_fields | [str] | [] | 候选字段名 |
| static_fields | {str:str} | {} | 固定提交参数 |
| success / failure | {body_contains:[str],url_contains:[str]} | {} | 判定标志 |
| needs_captcha / requires_js / deprecated | bool | false | |
| min_app_version | str | "" | 高于本机则跳过 |
| note / updated / source | str | "" | 出处 |
| **未知键** | — | — | **一律拒绝（strict）** |

示例（真实可用）：

```json
{
  "schema_version": 1,
  "id": "srun",
  "name": "深澜 SRUN",
  "priority": 100,
  "match": { "url_contains": ["srun_portal","get_challenge"], "body_contains": ["srun_bx1"] },
  "login_mode": "srun", "password_mode": "plain",
  "username_fields": ["DDDDD","username","user"],
  "password_fields": ["upass","password"],
  "success": { "body_contains": ["login_ok","e0000"] },
  "failure": { "body_contains": ["password_error","user_not_found"] },
  "note": "无表单：challenge+HMAC-MD5+xxtea，纯 HTTP"
```

### 2. `profiles update` 安全方案

前两层纯标准库：
1. **拉取**：`urllib.request` 走 HTTPS，host 用编译期白名单（raw.githubusercontent.com 等）；超时 8s；响应 ≤512 KiB；重定向不得跳出白名单。
2. **校验**：`json.loads` → **白名单 schema 校验**（键/类型/枚举/长度/数组上限，未知键拒绝）；清单内每个文件带 sha256，用 `hashlib` 逐个核对；`schema_version ≤ 本机`、`min_app_version ≤ 本机`，否则跳过并提示。
3. **签名（可选增强）**：本机存在 `minisign`/`cosign`/`gpg` 时，用 pin 死公钥验清单签名；否则要求用户首次显式 `--trust <sha256>`（TOFU）。
4. **原子+回滚**：下载到临时目录→全部校验过→`os.replace` 原子替换（留 `.bak`）；任一步失败**不动旧文件**，继续用内置规则。

**必须拒绝（白名单之外全拒）**：键名含 `script/code/eval/exec/cmd/shell/subprocess/os/sys/import/__`；任何 shell/表达式/模板；任何触发下载或写盘的 URL/路径字段；正则（ReDoS）；base64/二进制大块；软链；超长串/数组。规则永远只喂 `Profile.from_dict`，绝不 import/exec/eval。

### 3. 冲突消解与优先级

范式抄 **uBlock**（真实实现 `src/js/static-net-filtering.js`）：每条规则算一个**数值优先级**（block=10、allow/例外=30、`important` 再 +30、redirect=11），高分胜；另有 `badfilter` 显式作废某条。本项目落地：
1. 显式 `priority` 降序；
2. 同分比**特异度**：命中 url 记 2 分、body 记 1 分，token 越多越高；
3. 再同分按 id 字典序（确定、可测）；
4. `supersedes:["id"]` 作废内置规则（=badfilter），`disabled:true` 灰度下线。
首条命中即返回（现有 `identify` 已如此），保证确定性。

### 6. fixture 回归与脱敏自动化
