## 定位与边界

**定位**：Web 门户认证型校园网的「自启动 + 多平台 + 通用」自动重连程序。

**明确不做**（写进 README，避免无穷无尽的 issue）：802.1X / EAPoL、PPPoE 拨号、
客户端强管控（MAC 绑定、专有协议）、任何绕过计费的用法。

## 阶段 1 · 无人值守可用性（本周，改动小、风险低）

目标：**重启后不需要任何人登录，认证就能跑完**，并且状态可观测、不会双跑。

1. [ ] **Windows 自启动改为计划任务**
       开机触发 + 不管用户是否登录都运行 + 指定本人账户（不要用 SYSTEM，
       DPAPI 绑用户）。
       验收：注销到登录界面后重启机器，`http://127.0.0.1:2268/api/health`
       在无人登录时仍返回 `ok=true`。
2. [ ] **把 `lockfile.SingleInstance` 接进 `serve()`**
       现在锁已实现且有测试，但入口没调用；计划任务与启动文件夹叠加会导致
       两个监控线程写同一份 SQLite。
       验收：第二个实例启动时打印持有者 PID 并退出。
3. [ ] **日志落盘**
       `logging` + FileHandler（或至少 `PYTHONUNBUFFERED=1`），按天保留 N 天。
       验收：服务运行 5 分钟后 `database/` 下有递增的日志文件。
4. [ ] **多目标探活**
       2~3 个不可缓存目标，任一放行即算通；单个 canary 被拦时不再误判为掉线。
       验收：模拟单目标被拦，账号状态是 `online`，否则只能是「在线未确认」。
5. [ ] **凭据导出/导入**（解决换机、重装后 DPAPI 解不开的问题）
       验收：导出后用口令重新加密，可在另一台机器导入并成功认证。

## 风险清单

- **学校策略**：单账号多设备会互相顶下线；私接路由、长期隧道可能违反校园网管理办法。
- **凭据可迁移性**：Windows DPAPI 绑定当前用户与机器，换机/重装后必须重新录入，
  因此阶段 1 的导出/导入是刚需。
- **规则库信任模型**：规则包一旦允许代码，远端更新就等于任意代码执行。
- **自启动语义差异**：Windows 启动文件夹、XDG autostart、LaunchAgent 都是「登录后」，
  只有 systemd user + linger 才是真正的无需登录；WSL 与无桌面服务器会静默失效。
