## 移动端 APP：P1–P4（2026-10-15～16，收成 2.2.0）

起点是重新读了一遍目标：**电脑通电即连校园网，且开关机由人在远程决定**。控制台已经把
「连」那一半做完了，缺的是「开机」——后端进程要等开机之后才跑起来，所以任何网页都够不着
一台关着的机器。手机浏览器再顺手也补不上这个洞，只有能在手机上直接往局域网发广播的原生
代码才行。这是做 APP 的真正理由，不是「用起来方便」。

### 形态与选址

- 形态：**WebView 套壳**，控制台那半边一行没重写，APP 只加原生 WOL 与本地缓存。
- 放在 `project/mobile/`。不放进 `project/frontend/`，是因为后者的白名单会被
  `_serve_static` 经 HTTP 暴露给整个局域网，APP 源码不该能被别人下载走。

### 一个只有真后端才抓得到的坑

中转转发写完时，假服务器单测全绿，接上真后端却失败：客户端只看到
`HttpException: Connection closed while receiving data`，看着像「中转设备连不上」。真因
在 Dart 这一侧——`HttpClient` 只要写了请求体又没显式设 `contentLength`，就会改用 chunked
传输；而后端在 `_read_raw_body` 里明确拒绝 `Transfer-Encoding`，直接回 400 并断开连接。
唤醒接口本来就不吃请求体，改成显式 `contentLength = 0` 即可。假服务器会老老实实把 chunked
收下，所以这个坑单测永远看不出来——**跨端联调必须接一次真的**。

## 编辑账号的密码状态提示（2026-10-15，提交 `95fbb0c`，收成 2.1.2）

起点是用户的一句报告：「这里编辑不了，密码不保存，保存了之后不显示就好了呀」，
配一张编辑账号模态框的截图。紧接着他补了主目标：**让电脑通电后自动连校园网、不用他
到现场开机，开关机由他远程决定**。这句背景决定了本轮的优先级——账号密码配不上，
整条链路就是白搭，所以这一轮要解决的不是「界面好不好看」，而是**让用户敢确认密码
已经生效**。

### 先核实，别急着改

读代码 + 跑真浏览器，先把事实摆平。验证脚本建**自建随机端口 + 临时库**
（`ThreadingHTTPServer(("127.0.0.1", 0))`），**不碰 127.0.0.1:2268**：

| 检查 | 结果 |
|---|---|
| 编辑时填新密码保存 | PUT 200，库里 `password` 变为新值 |
| 再编辑、密码框留空保存 | 库里仍是新值，没被清空 |
| 密码框是否可编辑 | `is_editable=True`，`readonly` / `disabled` 均为 None |
| 页面 JS 错误 | 无 `pageerror` |

链路本来就是对的：`server.py:100-101` 那条「密码为空且没显式传值 → 保留原密码」的守卫
**从首个提交 `d4af7fa` 就在**，`storage.update_account` 也忠实写入。所以用户报的
「编辑不了、密码不保存」**不是数据问题**。

### 真正缺的是反馈

`Account.public()`（`storage.py:52`）刻意不含 `password`——这是对的：控制台可能经远程
访问打开，回显明文等于把密码贴在屏幕上。但代价是编辑框永远是空的，「原密码还在」和
「密码被清空了」在屏幕上长得一模一样。用户按提示留空保存、重开还是空框，只能得出
「没保存」的结论。他自己其实已经把答案说出来了——「保存了之后不显示就好了呀」：
他要的不是回显，是**确认**。

### 改了什么

1. `storage.py`：`public()` 多回一个 `has_password` 布尔（只有 true/false，不含任何
   密码内容）。界面这才有依据把状态说清楚。
2. `index.html`：编辑态标签去掉必填星号；占位提示按情况写「已保存，留空则不修改」或
   「这个账号还没有密码」；说明文字同步；保存后的提示明说「密码已更新」还是
   「密码未变动」，不再只回一句「已保存」。
3. 补用例：`test_server.py` 走 PUT 接口锁住「空串 = 不改、非空 = 覆盖」与
   `has_password`；`test_console_browser.py` 用真浏览器锁住上面几种界面状态。
4. `test_storage.py` 里 **`test_update_account_keeps_password_when_blank` 原本是空转的**：
   函数体把 `password` 赋成 `""` 又立刻赋回 `"p@ssw0rd"`，实际只断言了改名字。也就是说
   「留空保留原密码」这条语义**在此之前从没被验过**——这正是用户会怀疑它坏了的土壤。
   现在改成如实断言存储层的契约，语义交给 server 层那条用例。

### 验证

- `python -m pytest project/backend/tests -q` → **1293 passed / 11 skipped**（27 分 25 秒）
- `CAMPUSNET_BROWSER_CHANNEL=chromium python -m pytest project/backend/tests/test_console_browser.py -q`
  → **5 passed**
- 新增的浏览器用例**回退前端改动后会变红**（`git stash push -- project/frontend/index.html`
  实跑确认），不是自证式用例
- `python utils/check_distribution.py --repo .` → 91 个拟分发文件，0 命中
- 版本一致性用例 17 passed（`__init__.py` / `manifest.json` / CHANGELOG 三处同步到 2.1.2）

### 教训

**「功能是好的」不等于「用户不会报 bug」。** 这一轮如果只顺着报错去查数据层，会得出
「工作正常」然后什么都不改；真正要修的是「用户凭什么相信它正常」。凡是**刻意隐藏数据**
的地方（密码不回显、日志脱敏、只给状态不给值），都要同时给出**可确认的替代信号**，
否则用户只能靠猜，而猜错的代价是重装、重配、以为整条链路坏了。

另外：这次能一眼判定是反馈问题而非数据问题，靠的是**跑真浏览器把链路走了一遍**，
而不是只读代码——读代码只能证明「应该是对的」。

## 第十二轮：全项目审查，收成 2.1.1（2026-10-15，提交 `510263c`）

起点是用户那句「审查项目和代码」，随后是「你决定，完成后上传发布新版本」。范围由我定：
**修 P1 两条 + P2 里低风险且修法明确的一批**，需要改判定语义的一律跳过（理由见文末）。

### 修了什么（分四批）

**批 A 判定正确性**

1. **探活只看状态码、不看正文 → 门户回个 200 的登录页就判「已在线」**。这是本项目最不能
   出的错：用户以为连上了，实际没认证，监控也不会再重连。按 RFC 8952 的 canary 语义收口
   ——默认探针的正文必须命中 `Microsoft Connect Test` / `Microsoft NCSI`，204 类探针正文
   本来就是空的，单独放行。**顺手把 `ONLINE_MARKERS` 里裸的 `"ok"` / `"204"` 删了**：
   `"ok"` 在任意门户页里都可能出现（`book`、`ok?`），留着等于把这张表废掉。只对默认探针
   生效——用户自定义 `probe_url` 期望什么正文我们并不知道，拿同一张表卡它只会把正常网络
   判成掉线。
2. **`result=` 的边界太松，页面内联 JS 会把一次成功判成失败**。`(?<![\w])result\s*=`
   会命中 `var result=0;`，收紧成 `(?:^|[?&{])result`——只有出现在查询串或 JSON 形态里
   才算「门户在报结果」。后端 `portal.py` 与扩展 `classify` 两份实现同步改（第十一轮刚
   因为两份实现走岔栽过一次）。
3. **门户回 302 时拿错了 URL**。`_fetch` 对 3xx 返回的是入参 url（提交地址），而
   `classify_response` 正是要拿这个 URL 判「是否仍停留在登录页」——表单 action 多半含
   `login` / `portal`，于是一次正常的成功跳转被判成失败，白跑一轮重连。改成用 `Location`。
4. **非 ASCII 令牌头让服务端抛 `TypeError`**。`hmac.compare_digest` 对含非 ASCII 的 `str`
   直接抛，而 HTTP 头按 latin-1 解码，一个高位字节就够；鉴权门禁又在 `_dispatch` 的 try
   之外，异常逃出去就是连接被重置 + 一整段 traceback，客户端连 401 都拿不到——发个畸形头
   就能反复刷日志、耗线程。改按 UTF-8 字节比。

**批 B 通知与权限**

5. **「已恢复在线」会在用户从没收到过「已掉线」时发出去**。原来把 `_failures > 0` 也算作
   曾失败，`after_failures=3` 时「第 1 轮失败、第 2 轮恢复」就发一条没有前情的恢复通知；
   链路每两轮抖动一次就无限重复——正是本模块要避免的那种轰炸。改成只认
   `account_id in self._notified`。
6. **WAL / SHM 旁挂文件的权限只在建库时收过一次**。这两个文件在最后一个连接干净关闭时被
   SQLite 删掉，下次打开又以 umask（通常 0644）重建，而事件正文与 settings 会落在那里。
   改成每次建连接补收一次。

**批 C 扩展与控制台**

7. **10 秒一次的轮询会把账号表整块重建，正好吃掉用户的一次点击**。`innerHTML` 把全部
   节点换成新的，用户已按下的那颗按钮在 `mousedown` 与 `mouseup` 之间被替换掉，那一次
   点击就凭空消失。加结构签名（`_acctSig`，**刻意不含相对时间**——那串字每 10 秒都在变，
   放进签名等于永远命中不了，下面那层原地更新就白写了），签名相同且行数对得上就只原地
   刷 `.sub-time`；行数对不上说明这个 DOM 不是本函数建的（`refresh()` 的失败分支会清空
   容器），退回整块重建。
8. **控制台 `api()` 的 120 秒超时没盖住读正文**。`clearTimeout` 在 `finally` 里，早就跑完
   了，之后那个 `await res.json()` 没有任何保护——半开连接下「响应头到了、正文卡住」很
   常见，`refresh()` 永远不 settle，10 秒一次的轮询还在一轮轮往上叠。把 `res.json()`
   移进 try。
9. 扩展间隔下限夹到 0.5 分钟并写回输入框（原来界面显示 0.25、实际按 0.5 跑，而
   `type=number` 的 `min` 走手动 `onclick` 保存时拦不住手输）；扩展探活认
   `opaqueredirect`（扩展页 origin 下跨域 + `redirect:'manual'` 拿到的是 `status === 0`、
   headers 为空，一条分支都不命中，界面只显示「HTTP 0」，让人以为探测本身出错——而
   「被重定向」恰恰是未放行的表现）。

**批 D 交付与文档**

10. **Docker 一重建容器就丢密钥**。`crypto` 默认读 `~/.campusnet_obf.key`，而容器里的
    HOME 不在挂载点上——数据库还在，却没东西能解，账号密码全变成密文，而 README 承诺的
    是「挂一个卷就带得走」。加 `CAMPUSNET_KEY_FILE=/app/database/.campusnet_obf.key`
    （与 `docker-compose.yml` 的卷挂载点一致）。
11. **`install.sh` 不建安装目录的父目录**。默认装到 `~/.local/share/campusnet`，而
    `~/.local/share` 在最小化系统上并不存在，`git clone` 直接报 could not create leading
    directories（归档那条分支本来就有 `mkdir -p`，补的是另一条路）。
12. **发布流水线没有 tag 与版本号的一致性校验**。流程是先改 `__version__`、再推同名 tag，
    两处手工同步，漏改哪一处都不报错；而包名、二进制名、Release 标题全跟着 tag 走，
    `--version` 打出的是代码里那个。现在 `GITHUB_REF_TYPE=tag` 时比对，不一致直接
    `::error::` + exit 1。
13. `.gitattributes` 补 `utils/pre-commit` 与 `Dockerfile` 的 `text eol=lf`（前者按
    `cp utils/pre-commit .git/hooks/pre-commit` 用，带 CR 的 shebang 在 Linux/macOS 上
    根本不会执行，而它唯一的职责正是拦敏感串，坏了不会有人发现；后者靠行尾 `\` 续行，
    CR 会让 Windows 上检出后第一条 RUN 就失败）；README 的 dry-run 用法更正为
    `| sh -s -- --dry-run`（不写 `-s --`，`--dry-run` 会被 sh 当成脚本文件名）。
14. **`ports._who_holds` 用 `text=True` 读 netstat**。那是本地编码，而 netstat 写的是控制台
    代码页（中文 Windows 上是 GBK）；Python 处于 UTF-8 模式时解码在 subprocess 的读线程里
    失败，`stdout` 直接变成 `None`，于是本意是「告诉用户端口被谁占了」的诊断自己抛
    `AttributeError`。改宽松解码字节（这一行真正用到的只有 ASCII 部分）。

### 修了什么

**P1 四条**

1. **跨站 GET 能驱动本机干活（盲打 CSRF）**。`/api/probe`、`/api/discover`、

   `notify_key`）、读账号、关机**。
   **修法是归一化**：进 `_dispatch` 先把路径补成绝对路径，让下游（门禁 / 版本别名 /
   路由 / 静态）只见到一种形状。
   *复核时的教训*：第一次写验证装置**漏调 `_install_dispatch`**，用的是那份无鉴权的旧版
   `_dispatch`，测出来 `/api/accounts` → 200、`api/accounts` → 404，**和报告完全相反**。
   装上之后才得到正确对照（401 vs 200）。**结论与报告相反时，先怀疑自己的装置。**
2. **P0 · CI 全红（`test_menu.py`）**，我上一轮引入的。`test_register_bootstart_aborts_
   on_interrupt` 没注入平台：Linux 上 `mode="auto"`，压根不走 `getpass`，`install()` 返回
   installed=True → `return 0`，而用例断言 `== 2`。**本机是 Windows，走的是另一条分支，
   所以本地全绿。**「本机过 CI 不过」同因**第二次**复发了。
   日志逐字确认：`assert 0 == 2`，三个 Linux 版本各 1 failed / 1239 passed。
   修法是按同文件其它用例的既有写法补上 `CAMPUSNET_FORCE_PLATFORM=windows` 并 stub
   `install`（防的是「哪天分支改回去，用例变成往 `~/.config/systemd/user/` 写文件」）。
3. **H · 指路指向不存在的快捷方式**（`bootstart.py` / `powerprep.py`）。两处都让人去点
   「校园网自连（以管理员身份）」或「自我提权」快捷方式——`shortcuts.py` 的
   `DEFAULT_SHORTCUTS` 只产出「校园网自连」一个入口，`create_windows_elevated` 生产代码
   零调用。改指真实路径：菜单（它会主动提出提权重试）+ 管理员终端里那条命令。
4. **H · 通知发送失败被记成「已发送」，且永不重试**（`notify.py`）。
   `observe()` 先 `_notified.add(account_id)` 再 `send()`，**返回值被丢弃**，然后
   `return kind`；`monitor.py` 见 `if kind:` 就写下「已发送…通知」。后果：webhook 恰好
   不可达那一轮之后，每一轮都在 `_notified` 上短路——**通知永远补不上，日志还谎报已发送**。
   改成「发送成功才落账」，失败返回空串（让它别记账也别写日志）。顺带把
   `event_enabled("failing")` 的检查挪到落账之前，让 `_notified` 只表示「已告知掉线」。
   原来的 `test_send_failure_is_swallowed` **正是把这条缺陷当预期写死的**（断言失败也返回
   `"failing"`），已改成回归测试 + 新增「失败后连试三轮最终补上」的用例。
5. **H · 裸「在线」子串把失败判成`already_online`**（`portal.py`）。`already_online` 的
   `ok` 为 **True**，而这一条又排在**密码错误检查之前**——被盖住的那次不落 `terminal`，
   600 秒冷却不启动，程序拿着错密码一轮轮重登，**有锁号风险**。另外裸子串会命中
   「在线客服」「当前在线人数」这类页面。
   改法两条：**去掉裸「在线」**（换成「已在线」「已经在线」等完整措辞——注意
   「您已经在线」里**没有**连续的「已在线」三个字，原来那条裸子串纯属蒙对），
   **并把这一条挪到密码错误 / userdeny 两条终态判定之后**，但仍在 `result:0` 这类
   通用失败标记**之前**（Dr.COM 的已在线应答可能就长成 `{"result":0,"msg":"您已在线"}`，
   那些标记比这条更弱）。

## 第七轮：把 `--mode task` 接进 HTTP API（2026-10-14，提交 `58ec61e`）

第六轮把 `--mode task` 从菜单和 `setup` 里摘干净了（它只在 Windows 上有意义），但顺带
留下一句「这条路要走命令行或 `packaging/`」——**远程打开控制台的人还是做不了这一步**，
而这正是这个项目的主要使用场景（人在外面，机器在宿舍）。所以这一轮把它接进 API。

两个决定是先问过的，不是顺手做的：

1. **凭据怎么进**：浏览器输入框 → `POST /api/bootstart/install`，body 里带
   `{"mode": "task", "password": "..."}`。选的不是「走命令行」也不是「本地文件」——
   理由是这个项目里**已经有同样的先例**：校园网账户密码本来就走 `POST /api/accounts`
   明文 JSON 进库。同一条信任边界，不额外发明一套。
2. **失败怎么报**：如实把后端错误原文显示在页面上。非管理员账户注册计划任务会被系统
   拒绝，那句错误里带着用户唯一能拿到的指路——吞掉它，用户就只看到「未开启」而不知道
   下一步该干什么。（**那句指路本身是错的，已在第八轮更正**：它让人去点
   「校园网自连（以管理员身份）」快捷方式，而桌面从来没有过这个东西。）

### 改了什么

- `server.py` 的 `bootstart_install` 接受 `mode` / `password` 并校验：`mode` 只认
  `auto` / `task`，`password` 必须是字符串，非 Windows 上传 `mode=task` 返回 **400**
  （不是让 `install()` 抛成 500——请求本身就不对）。事件文案带上模式
  （`开机自启动安装请求（task）-> …`），但**不含密码**。
- 控制台设置页多一行「免登录启动」（`#bootTaskRow`，仅 `platform === 'windows'` 时
  显示），密码框 `type="password"`，注册后立即清空。这里踩到项目里反复出现的
  `[hidden]` 陷阱：`.row{display:flex}` 会盖掉 `hidden` 属性，必须补一条
  `#bootTaskRow[hidden]{display:none}`（和之前 `.install-bar[hidden]` 同一个坑）。
- 密码的处置口径写进注释与页面提示：只交给任务计划程序保存一次，不落库、不进事件
  日志、不进响应。

### 顺手修的一个真缺陷

**控制台注册失败时不显示原因。** 失败分支里先 `toast()` 一次、再写 `bootHint`、
最后 `await loadBootstart()`——而 `loadBootstart()` 会用 `status()` 的 detail 覆盖
掉刚写的那句，页面上只剩「未安装开机自启动」。写这段时照抄了既有 `setBootstart`
的顺序但抄反了（那边是「先刷新、后写提示」）。改成同样的顺序后，后端错误原文能留住。

### 这一轮验证了什么

- `python -m pytest project/backend/tests -q` → 见本轮提交前的整体结果（新增 4 项
  `test_server.py` 用例：默认参数变成 `auto`/空密码、`task` 模式转发密码且密码不出现在
  响应与事件里、非 Windows 上 `task` 返回 400 且不调用 `install`、三种坏 body 都 400）。
- 控制台用静态 `http.server` 起 `project/frontend`，在浏览器里打桩 `window.api` 后
  实际点击验证：`windows` 平台上该行 `display:flex`、`linux`/`darwin` 上为 `none`；
  空密码不发请求；提交后发出的是 `{mode:'task', password:'hunter2'}` 且输入框被清空；
  **失败路径现在页面留的是后端原文**，徽章仍照常刷新回「未开启」。

## 第六轮：开机自启（2026-10-14，提交 `eecc5d7`）

主题是「开机自启」。**起因是一次方向性纠错**：记忆里把「Linux 没 `enable-linger`、
macOS 没 `launchctl bootstrap`」当成待补的真实缺陷，这一轮先去读了 `packaging/` 下
两份系统级单元和 README 的自启动一节——用户级载体是「登录后」语义**是刻意的取舍**
（不写系统级位置、不动账号级设置），「无需登录」的正解是系统级单元（需 root）或
Windows 的 `--mode task`。方向改过来之后，真正的问题才浮出来，一共四处：

1. **主菜单的「注册开机自启」在 Linux / macOS 上从来没能用过**（真缺陷）。这一项不分
   平台一律先要一次 Windows 账户密码、再按 `mode="task"` 装，两个平台上必然失败在
   「计划任务模式目前只支持 Windows」。现在按平台选载体——Windows 仍走计划任务，
   密码也只在那条路上才要。
2. **「已注册开机自启动」这句话分不出「开机就连接」还是「登录后才连接」。** 四个用户级
   载体都是登录后语义，而 `install()` 只报前半句；macOS 的 `status()` 说「已注册开机
   自启动」，同文件里的 `verify()` 却说 LaunchAgent 只在图形会话里跑——**同一件事两处
   口径相反**。现在三平台的 `install` / `status` / `verify` 统一说「登录后才会拉起」，
   并各自给平台专属的替代路径（新增 `bootstart.unattended_hint()`，散在 CLI / 菜单 /
   install / status 四处的文案收成一处）。
3. **命令行把 Linux 用户指向 linger。** 那条提示与 README、与项目设计都是相反的，
   一并删掉。
4. **两处「说明 / 下一步」承诺了做不到的事**：控制台说点「开启」会弹 UAC 并索取
   Windows 账户密码——按钮实际调 `/api/bootstart/install`，注册的是用户级载体，UAC 与
   密码都不存在；`setup` 报告的「下一步」在三个平台共用一句「同意 UAC 并输入密码 →
   通电就会自动认证，不需要任何人登录」。都改成照实描述。

菜单副标题也跟着动作走（`bootstart_hint()`）：「注册开机自启」在非 Windows 上不再写
「无需登录（需要管理员）」，改为说明登录后语义与系统级单元这条替代路径。

## 第五轮：多端入口（2026-10-14，提交 `8f3a2c7`）

主题是「多端入口」，起因是用户那句「控制台**以及其他多端的快捷方式**」。先把现有的
多端入口逐个查了一遍：PWA 的 `manifest.webmanifest`（`display: standalone`）、
service worker（network-first + 离线回落，`/api/` 不缓存）、`apple-touch-icon`、
桌面快捷方式合并成单一入口——**这些都已经就位**。真正缺的是三件小事：

1. **菜单里选「启动服务」而服务已在跑时，整个窗口会直接关掉（真 bug，真机复现过）**。
   `serve` 撞上「已有实例运行」是 `raise SystemExit(1)`，`cmd_serve` 显式 re-raise，
   而 `run_menu` 没有接住——退出码穿透到进程。桌面快捷方式双击进来的是一个 cmd 窗口，
   一闪而过，用户连那句 `[错误] 校园网自连服务已有实例运行（持有者 PID 21904）。`
   都来不及看。现在 `run_menu` 接住 `SystemExit` 并如实回报退出码；**退出码 2 当作
   「用户取消」不报**（`guided_add`、`register_bootstart` 取消时返回的就是 2），
   否则每次 Ctrl+C 取消都要多挨一句。真机复测：菜单存活、退出码 0，PID 21904 未受影响。
2. **菜单没有状态首屏**。十几个功能一字排开，账号几个、最近什么时候检测过、服务在不在跑
   都得先翻「自检报告」。新增 `status_line()`：账号数（启用几个）· 最近检测多久前 ·
   服务运行中 / 未启动。读库失败或端口探不通就省略那一段——报状态失败不该让菜单起不来。
   端口探测给 **0.5 秒短超时**，理由与 [[local-dead-port-drops-packets]] 一致：本机未监听
   的端口是丢包不是立刻拒绝，不给超时菜单就卡在那儿。
3. **「添加到主屏幕」的引导没到用户手上**。manifest 和 service worker 早就位了，
   但既不在 `access` 的输出里，控制台也不提。现在控制台在触屏设备显示一条提示：
   浏览器给了 `beforeinstallprompt` 就带「安装」按钮，没给（iOS Safari 只能走分享菜单，
   且 iPadOS 13+ 的 UA 是 Macintosh、要靠 `maxTouchPoints` 区分）就退化成指路文案；
   点过「不再提示」或已装过（`display-mode: standalone`）就不再出现。**桌面端不提示**，
   那边有书签和扩展。`access` 输出补两行（手机端建议 + 快捷方式），主菜单另开一条
   **远程接入向导**入口——没有把 `--guide` 并进「查看多端访问」，因为向导会拿掉令牌
   那一行，而令牌正是手机首次登录要用的。

### 这一轮踩到的坑（都验证过）

- **`[hidden]` 会被 `display:flex` 盖掉**。提示条用了 `display:flex`，光设 `hidden`
  属性不生效，条子会永远挂在首屏上。自定义 `display` 的组件必须自己补一条

## 第二轮审查：安全取舍与电源体检（2026-10-14）

上一轮审查留下 6 条需要取舍的项（B1–B6），这轮做了 B1、B3，顺带修掉两条用户可感知的
缺陷；B2 / B4 / B5 / B6 **主动跳过**，理由记在下面。改动清单与理由见 `CHANGELOG.md`
的 `未发布` 段，这里只记结论、取舍与验证方式。

**B1 免令牌模式的 Host 门禁（DNS 重绑定）**

机制：服务绑回环又没开令牌时 `auth_required=False`、`auth=None`，唯一的守门是
`require_same_origin`；而它比的是 `Origin` 与 `Host` 是否相等、且只对写方法生效。
攻击者把自有域名解析到 `127.0.0.1` 后，浏览器认为「页面」与「被访问的服务」同源，
两者天然相等，同源校验和浏览器本身都看不出异常——读 `/api/settings`（含 webhook 密钥）
与调 `/api/power/off` 都拦不住（GET 连 `Origin` 都没有）。

**没有一刀切删掉同源校验**：反代同源是本项目有意提供的功能（本文件「深度优化 v2」段里
写着「写接口统一来源校验，支持 HTTP/HTTPS 反代使用相同 Host」），删掉等于砸掉既有用法。改法是默认拒绝非回环 Host，
`CAMPUSNET_TRUST_PROXY=1` 显式放行，把取舍交回部署者声明。两个实现要点：

- 门禁**连 GET 一起挡**——重绑定下浏览器拿得到读接口的响应；
- 必须放在 `_dispatch` 的 `try` 块**内**。抛在外面时 `ApiError` 逃出 `_dispatch`，
  客户端只收到连接重置、读不到 403 的原因。

影响面：`--host 0.0.0.0` 时 `auth_required=True`，门禁不生效；扩展（走 `127.0.0.1`）、
CLI、控制台都不受影响。唯一受影响的是「回环监听 + 反代 / Tailscale Serve」这一种，
403 报文里直接点名了那个环境变量。

**B3 设置项白名单（顺带修掉一个持久化 DoS）**

原 `PUT /api/settings` 不校验类型，一条 `{"interval": "abc"}` 就能落库；此后
`MonitorManager.ensure()` 每次启动都在裸 `int()` 上抛异常，**重启也一样**，只能手改数据库。
修法两层：API 边界按白名单校验类型（未知键 400；`bool` 必须单独判——它是 `int` 的子类，
不单独判的话 `True` 会被当成 `1` 悄悄写进去），且**整批校验通过才落库**，一条坏值不会
让前面几条写进去、后面几条没写；读取侧加 `_int_setting` 兜住库里已有的脏值。
边界挡新脏值，读取侧救已经坏掉的库，两层都要。

**顺带修的两条（用户可感知）**

- `power prep --fix` 那句确认在**没有终端**时（双击快捷方式、计划任务、stdin 被重定向）
  会抛 `EOFError`，Ctrl-C 则抛 `KeyboardInterrupt`，整条调用栈直接冒到用户面前。
  现在按「取消」处理，与 `menu.py` 已有的 `except (EOFError, KeyboardInterrupt)` 惯例一致；
  读不到确认就等于没确认，绝不顺手改注册表和 `powercfg`。
- 电源体检里「网卡魔术包唤醒」那项在 PowerShell 的 NetAdapter 模块不可用时标着
  `fixable=True`，但它自己也写着「请手动…」，`--fix` 会落回同一条分支、什么也改不了。
  CLI 的「将尝试自动修复」和控制台的确认框都按 `fixable` 统计，于是用户确认一圈却
  什么都没发生。改成 `False`。

**主动跳过的四项及理由**

1. **B2 遮蔽 `/api/settings` 回显的 webhook 密钥**：B1 落地后，免令牌模式下非回环 Host
   一律 403，唯一实际读取路径已经堵死；再改成「只写不读回」需要配套改前端，
   有把用户密钥**静默清空**的风险，收益不抵风险。
2. **B4 收窄扩展的 `host_permissions`**：改的是 MV3 后台的权限模型，本机无法加载扩展
   做真实验证——违反「安全第一、宁慢不冒险」，不动。
3. **B5 把控制台浏览器交互测试升为必过检查**：会引入 flaky。它是「再加一道门禁」，
   不是「修一个缺陷」。
4. **B6 CI 成本收敛**：低价值，且有改坏工作流的风险。

## 阶段 E 收尾：CI 转红（2026-10-13 晚；10-14 复核，**ubuntu 已修并推送，windows 待新运行定论**）

（`ubuntu-latest` × 3 + `windows-latest` × 3，Python 3.10 / 3.12 / 3.13）
「单元与接口测试」步骤**全部失败**；另 3 个作业（控制台浏览器交互、浏览器扩展逻辑、
仓库不得包含凭据）通过。这段区间此前**从未被 CI 跑过**（`b721887` 是上一版 main 头，
阶段 A~E 的改动是第一次进 CI），所以不是回归，是首次暴露。

判定依据：失败**与 Python 版本无关**（3.10 / 3.12 / 3.13 一样红），所以不是解释器差异；
该步骤耗时 ubuntu 126~210 s、windows 386~413 s，**都跑满了整套用例**，

### 已定论：ubuntu 的根因（已修，随 2026-10-14 的推送重新触发 CI）

`project/backend/campusnet/shortcuts.py` 的 `desktop_dir()` 是文件里**唯一**直接读
全局 `os.name` 的地方，绕过了本项目自己的平台抽象；两条用例则用
`monkeypatch.setattr(shortcuts_mod.os, "name", "nt")` 伪装平台。`os` 只有一个全局模块，
补丁会**漏进 pathlib**，于是 `Path.home()` 在 Linux 上按 `'nt'` 去实例化 `WindowsPath`，
`WindowsPath.__new__` 在非 Windows 上无条件抛 `NotImplementedError`
（3.13 上是 `UnsupportedOperation`，同样是 NotImplementedError 子类）。

项目自己在 `power.local_macs(platform=...)`（注释「platform 参数供测试注入，避免为了测试
去改全局的 os.name」）和 `bootstart.platform_name()`（`CAMPUSNET_FORCE_PLATFORM`）里
就有注入平台名的先例。修法就按这个先例：

- `desktop_dir(platform: str | None = None)` 改用 `platform_name()` 判定；
- `create()` 把已解析的 `name` 传下去，避免二次查平台；
- 两条用例改成注入 `platform="windows"`，删掉全局 `os.name` 补丁。

**同类点复查后不动**：`test_bootstart.py:763`、`test_crypto.py:77`、`test_power.py:376`、
`test_platform.py:511/531/540/548/561/578` 也打全局 `os.name`，但 Linux 容器复现里
全部通过——`test_platform.py` 那组甚至在注释里写明了「必须先建好 `Path` / `SingleInstance`
再改 `os.name`」的原因，`test_crypto.py` 的 `posix` fixture 同时固定了混淆密钥，
不碰真实用户目录。既然不红就不动（最小侵入）。

### 已定论：原先记的另外 3 条是复现假阳性

- `test_bootstart.py::test_linux_install_falls_back_to_desktop_without_systemd`、
  `::test_linux_install_wraps_write_error`：容器内核是
  `6.18.54.1-microsoft-standard-WSL2`（Docker Desktop 走 WSL2 后端），
  `is_wsl()` 读 `/proc/version` 命中 `microsoft` → 走了 WSL 分支直接早返回，
  真实的 ubuntu runner 不会。**是复现环境污染，不是用例问题。**
- `test_precommit_hook.py::test_repo_is_clean_under_distribution_scan`：
  `git archive` 导出的树不带 `.git`，而 `check_distribution.py` 靠
  `git ls-files` 定文件集，没有 `.git` 直接 `CalledProcessError`。
  换成 `git clone`（带真实 `.git`）后**通过**。同样是复现方式造成的。

`test_precommit_hook.py` 是 **F5（`52d9905`）新增**的文件，`b721887` 上不存在——

跑不出对照（10-13 晚就是这么失败的）。

覆盖率不是原因：Linux 容器里 92.93%、windows 本机 94.07%（含修法的工作区全量
`1133 passed / 6 skipped`），都过 90% 门禁。

### 已定论：windows 的根因（2026-10-14，本机抓到的）

**跟 Windows 无关，跟「那台机器 80 端口有没有人应答」有关。**

链路：用例的 seed 是 `http://127.0.0.1:<随机端口>`，`discover()` 会取
`urlsplit(seed).hostname` 交给 `detect_dns_hijack()` 判「域名被解析到内网」；
`127.0.0.1` 命中了 `_is_private_ipv4` 的 `a == 127` 分支，于是返回 `"127.0.0.1"`，
`discover()` 就**凭空多塞一个候选 `http://127.0.0.1/`（80 端口）并真的去取**。

- 本机 80 端口没人应答 → 那条候选被丢掉 → 4 条用例绿；
- `windows-latest` 上 80 端口被系统服务占着 → 那份无表单页面进了候选
  （`username_field=""`），断言当场不成立 → 4 条用例红。

失败用例名（借着 `2123ddb` 那次「失败用例名写成注解」的步骤，匿名就能读到）：

```
test_discovery::test_dump_is_json
test_discovery::test_discover_reports_probe_state
test_discovery::test_discover_candidates_sorted_by_credibility
test_server::test_discover_endpoint_without_scan
```

决定性实验：在 `127.0.0.1:80` 起一个无表单 HTML 页，本机立刻复现出**同样的 4 条红**
（`4 failed, 168 passed`）；给 `detect_dns_hijack` 打临时补丁（回环直接返回 None）
后，80 端口仍被占着也是 `4 passed`。落地修复后：80 端口占用 → `172 passed`，
空闲 → `39 passed`。

修法：`detect_dns_hijack` 里把回环（`localhost` / `::1` / `127.*`）与 IP 字面量
直接排除——回环就是本机，IP 字面量压根没有域名，两者都谈不上「域名被劫持」。

这也解释了为什么此前三条忠实的 Windows 复现全绿：它们跑在本机，而本机 80 端口空着。

## 三、本轮修复过的问题

按根因修复，不是表面兜底：

1. **`crypto.obfuscate` 遇中文/emoji 崩溃** —— 原本按 `ord(c)` 逐字符异或，
   非 BMP 字符超出字节范围。改为先 UTF-8 编码再对字节流异或。
2. **`parse_forms` 完全解析不出表单** —— 原本用 `_TAG_END_RE.split()` 切分，
   会把 `<form>` 开标签本身一起切掉。改为按 `<form>` 位置切片 + `finditer` 定位闭合标签。
3. **`/api/accounts/{id}/login` 返回 500** —— 从路径末段切字符串取 ID，
   遇到尾部 `/login` 就切成 `"login"` 导致 `int()` 失败。改为从路由参数 `ctx["params"]["id"]` 取值。
4. **账号字段误判为 `user_ip`** —— Dr.COM 表单里 `user_ip` 带默认值且命中字段名启发式。
   改为跳过有默认值的隐藏字段。
5. **密码字段误判为 `hiddenPwd`** —— 按字段名匹配先命中了隐藏域。
   改为优先按 `type="password"` 判定。
6. **网关推导错位** —— 固定推 `x.y.z.1`，但 `/16` 掩码下网关在 `x.y.0.1`。
   改为 `gateway_candidates()` 同时给出两个候选，由扫描去判定。
7. **扫描可能空转数十秒** —— 逐网关全量扫描。改为命中即停 + 每网关限额。
8. **启动脚本在中文路径下失效** —— `PYTHONPATH` 含中文时被 shell 截断。
   改为 `utils/run.py` 在 Python 内部处理 `sys.path`。
