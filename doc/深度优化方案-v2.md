## 0. 一页速览

三句话结论：

1. **内核已经够好，短板在"最后一公里"。** 813 条测试、87% 覆盖、凭据 fail-closed、门户规则数据化——这套工程水平在同类开源项目里属于上游。真正拖后腿的是安装、无人值守自启、手机端体验，以及"宿舍晚上断电"这个真实场景的闭环。
2. **全网同类项目里值得抄的只有四家**：`Mmx233/BitSrunLoginGo`（分发面：路由器 / 容器 / 多架构）、`neucn/ipgw`（一行命令安装）、`seriousm4x/UpSnap`（WOL 面板 + 定时任务 + 设备管理，6.3k 星）、`mel0nyrame/LinkUp`（"先判断 → 再登录 → 最后确认"的状态机 + 手机端形态）。
3. **远程开机有一条物理铁律**，必须写进 README 最显眼位置：**WoL 是二层广播，跨不了路由器，Tailscale 也发不了**（Tailscale 官方博客原话）。宿舍断电场景的可行解只有两条：BIOS「来电自启」+ 智能插座，或宿舍里留一台常开小设备当跳板。

### 3.2 必修（P0）

**P0-1｜README 里的命令会直接报错**

- 证据：`README.md:576` 写着 `python utils/run.py openapi --out docs/openapi.json`，但仓库里没有 `docs/` 目录；
  且 `cli.py:480-483` 直接 `Path(args.out).write_text(...)`，不创建父目录 → `FileNotFoundError`。
- 做法：`cmd_openapi` 加 `Path(args.out).parent.mkdir(parents=True, exist_ok=True)`；README 示例改为
  `doc/openapi.json`；全仓 `docs/` 统一为 `doc/`（含文档内互链）。
- 验收：把 README 那行原样复制执行，退出码 0 并生成文件。

**P0-2｜Release zip 里的 README 是断链的**

- 证据：`release.yml:39-45` 只 `cp` 了
  `project utils database/schema.sql database/config.example.yml README.md LICENSE install.bat install.sh`，
  **没有 `doc/` 与 `packaging/`**。而 README 引用了 `doc/images/console-dashboard.png` 与
  `packaging/campusnet.spec` → 解压后图片 404、构建命令路径不存在。
- 做法：打包白名单加入 `doc/images`（只图片）与 `packaging/`；**不要整目录 `cp -r doc/`**
  （里面有内部文档 `工作状态存档.md`，不该发给用户）；同步在 `check_distribution.py` 的
  白名单/扫描规则里加一行注释说明为什么这样切。
- 验收：本地跑一遍 `release.yml` 的收集步骤（或临时脚本），解压 zip 后
  `doc/images/console-dashboard.png` 存在、`packaging/campusnet.spec` 存在、
  `doc/工作状态存档.md` **不**存在。

**P0-3｜没有"一行命令安装"**

- 证据：仓库只有 `install.bat` / `install.sh`，新用户仍要先 clone 或解压 zip；
  对照 `neucn/ipgw` 的 `iwr ... | iex` 形态。
- 做法：新增 `install.ps1`（Windows）与把 `install.sh` 升级为可管道执行版：
  - `iwr -useb https://raw.githubusercontent.com/enmingxiong821-cloud/campusnet/main/install.ps1 | iex`
  - `curl -fsSL https://raw.githubusercontent.com/enmingxiong821-cloud/campusnet/main/install.sh | sh`
  - 脚本硬性要求：幂等可重复执行；检测 Python ≥3.10 并给出安装指引；已存在安装目录时走"升级"分支而不是报错；
    下载 Release 产物时**校验 `sha256`**；全程中文可读输出；出错时打印下一步该干什么；支持 `--dry-run`。
- 验收：在干净的临时目录里跑一遍（至少 Windows 侧实测），产出可用的安装目录 + 桌面唯一快捷方式 + 自检通过。

**P0-4｜"断电恢复"只有文字，没有可验证的动作**

- 证据：`power.py` 的 `wake_info()` 返回的是 4 条中文说明；README 第 459-471 行也是叙述。
  用户真实诉求（浏览器批注原文）是"**只要电脑通电这个程序自动跑，自动连接我设置好的网络，然后电脑开不开机由我远程决定**"，
  以及"**晚上宿舍断电，还要能远程开机**"。这两条目前没有任何"检查→修复→自证"的能力。
- 做法：新增 `power prep`（别名 `doctor --power`），逐项体检并给出三类结论 `OK / 已修复 / 需人工`：

  | 体检项 | 检测方式（Windows） | 可否自动修复 |
  |---|---|---|
  | 快速启动是否关闭 | 注册表 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power\HiberbootEnabled` | 需管理员，`--fix` 可改 |
  | 网卡是否允许魔术包唤醒 | `Get-NetAdapterPowerManagement`（`WakeOnMagicPacket`、`WakeOnPattern`、`EnableWakeOnLan`） | 需管理员，`--fix` 可改 |
  | 哪些设备处于"可唤醒"状态 | `powercfg /devicequery wake_armed` | 只读 |
  | 睡眠/休眠超时 | `powercfg /query` 解析 AC 下的 `standby-timeout-ac` / `hibernate-timeout-ac` | `--fix` 建议设为 0（只关显示器） |
  | 远程桌面是否开启 | `fDenyTSConnections` | 需管理员 |
  | 是否已配置自动登录 | `AutoAdminLogon` | 仅提示（涉及口令，不自动写） |
  | 是否有管理员权限 | 令牌检查 | 只读 |
  | 时间偏差 | 与门户 HTTP `Date` 头比对，>5 分钟就告警（断电后主板电池老化会导致 HMAC/HTTPS 失败） | 只读 |
  | BIOS 来电自启 | 读不到，输出主板型号 + 对应键位的图文指引 | 人工 |

  非 Windows：Linux 输出 `wol`（ethtool）、`systemd` 目标、`rtcwake` 可达性；macOS 输出 `pmset` 相关项。
- 验收：Windows 上 `power prep` 输出一张全项表格（每项带结论与下一步），`--fix --yes` 能自动修
  快速启动与网卡唤醒并复检为 OK；所有修复在输出里写明"如何改回去"。

**P0-5｜无人值守自启的"最后一公里"还是靠人肉**

- 证据（本机实测）：当前登录账户是**普通用户（非管理员）**，
  `schtasks /Create ... /RP` 与 `Register-ScheduledTask -User -Password` 均被拒（Access is denied）。
  现有实现会提示提权，但注册失败的原因、以及"注册后怎么证明真的生效"没有闭环。
- 做法：
  1. 注册失败时把原始错误码翻成人话（例如 `Access is denied` → "当前账户不是管理员，
     注册'无需登录'的计划任务需要一次 UAC 授权"），并给出可点击的自我提权路径；
  2. 计划任务参数补齐：**三个触发器**（`ONSTART` + `ONLOGON` + 会话解锁）、
     `-RestartCount 3 -RestartInterval 1m`（任务级重试）、`-StartWhenAvailable`、
     电源条件"允许在电池上运行"、`-ExecutionTimeLimit 0`；
  3. 新增**看护任务**（每 5 分钟）：`/api/health` 不通就拉起服务（`campusnet serve`），
     避免"进程崩了但计划任务不会重启"的静默失效；
  4. 新增自证命令 `campusnet bootstart verify`：注销到登录界面后仍能拿到
     `/api/health` 返回 `ok=true` 才算通过，把结论写进日志。
- 验收：`bootstart install --mode task` 在非管理员账户上给出准确原因与提权入口；
  提权后注册成功，`bootstart verify` 输出"已生效"。

### 3.3 该做（P1）

**P1-6｜手机端还是"能用但不顺手"**

- 证据：`frontend/index.html` 只有一行 `viewport`（第 5 行），**没有 manifest、没有 service worker、没有图标**；
  `access.py` 让用户手抄 43 字符令牌。
- 做法：
  1. 加 `manifest.webmanifest` + `service-worker.js` + `icons/`（复用扩展里已有的 16/48/128 图标，补 192/512），
     支持"添加到主屏幕"，脱离浏览器地址栏运行；
  2. 控制台加**配对二维码**：`/api/pair` 生成一次性配对码（默认 5 分钟过期、单次使用），
     手机扫码 → 自动带码换取正式会话 Cookie（不必手抄令牌）；配对记录进事件日志，便于发现异常配对；
  3. 首页给"关机 / 重启 / 立即检测"三个大按钮（拇指可达、放在首屏），并加防误触二次确认。
- 验收：手机浏览器打开 → 扫二维码 → 直接进控制台；添加主屏幕后图标正常、离线打开显示"服务不可达"而不是白屏。

**P1-7｜分发面太窄**

- 证据：Release 只有 `windows-x64.exe` + 源码 zip（`release.yml:149-153`）。
  而同类项目 `BitSrunLoginGo`、`zu1k/srun`、`iskoldt-X/SRUN-authenticator` 都能跑在**路由器 / 树莓派 / NAS** 上——
  这恰恰是"宿舍断电也要保持在线"的最优解载体。
- 做法：
  1. `release.yml` 加矩阵：`linux-x64`、`linux-arm64`、`macos-arm64`（PyInstaller 单文件），
     命名统一 `campusnet-<版本>-<平台>-<架构>`；
  2. 新增 `Dockerfile`（`python:3.12-slim` 多阶段，非 root 用户，`/data` 挂卷）
     与 `docker-compose.yml`（`network_mode: host`、`restart: unless-stopped`、
     `HEALTHCHECK` 打 `/healthz`、环境变量注入账号口令，不落盘明文）；
  3. 推到 GHCR：`ghcr.io/enmingxiong821-cloud/campusnet:latest` +
     多架构 manifest（amd64/arm64/armv7），并**顺便做 Tailscale sidecar 的 compose 示例**
     （照 Tailscale 官方博客的三步走：Pi/容器 + `etherwake` + 面板）；
  4. `campusnet.service`（systemd **system** 单元，`Restart=always`）与
     macOS `LaunchDaemon` plist 模板放进 `packaging/`，供"开机即运行、无需登录"使用。
- 验收：`docker compose up -d` 能在任意有 Docker 的机器上起来并通过 `/healthz`；
  Release 页面出现 3 个新二进制且各自 `--version` 正常。

**P1-8｜通知只有通用 webhook**

- 证据：`notify.py` 只有通用 webhook；用户实际会用的是手机端推送。
- 做法：内置渠道预设 `bark` / `serverchan` / `wecom`（企业微信机器人）/ `dingtalk` /
  `telegram` / `ntfy`，配置项从"填一个 URL"升级为"选渠道 + 填 key"；
  事件分级：认证成功、认证失败、恢复在线、掉线、电源动作、配对成功，每类可单独开关。
- 验收：每个渠道至少一条 fixture 级测试（不真发网络请求，断言 payload 形状），
  配置页可选渠道并"发送测试通知"成功。

**P1-9｜没有"远程接入"向导**

- 证据：`access.py` 只列本机/局域网/Tailscale 地址与令牌（第 67 行还会建议 `--host 0.0.0.0`）。
- 做法：`campusnet access --guide` 输出一份可照做的三步向导：
  ① 装 Tailscale（给出下载链接与各平台一行安装命令）② 装远程桌面（RustDesk 优先，国产网络友好）
  ③ 手机怎么点（含二维码）；同时检测本机 `tailscale` 是否在跑、是否已登录、以及
  `tailscale status` 的精简摘要。**不改网络配置，只做检测与指引。**
- 验收：在没装 Tailscale 的机器上输出"缺第 ①步"并给出确切命令；装了并登录后显示 tailnet 名称与对端数量。

**P1-10｜远程开机缺"定时"与"多设备"**

- 证据：`power.py` 只有单次 `wake(mac)`；UpSnap 的 cron 定时事件与设备列表是本项目缺的那半。
- 做法：新增"唤醒计划"（每天/每周 N 点发 WOL 到指定 MAC，用系统本地时间，支持多个计划）
  与"设备清单"（名称 + MAC + 备注，可一键唤醒）；计划写入现有 SQLite，任务由 monitor 线程统一调度，
  不新起进程。UI 放在控制台"电源"页，与关机/重启并列。
- 验收：建一个"每天 07:30 唤醒"的计划，把系统时间改到 07:29，60 秒内观测到魔术包发出（mock socket 断言）+ 事件日志有记录。

**P1-11｜多网卡 / 指定网卡 / 门户自动发现增强**

- 证据：`power.local_macs()` 已经会把"已连接"的网卡排前面（很贴心的细节），
  但认证侧没有等价的"用哪块网卡认证"控制；同类项目 `zu1k/srun`（四策略）、
  `BitSrunLoginGo`（`--interface`）都做了。
- 做法：`add` / `check` / `serve` 支持 `--interface <名称或 IP>`（Windows 用 `--adapter` 别名），
  绑定出口网卡/源 IP，避免有线+无线同时在线时把 IP 认错；门户自动发现补
  "DNS 劫持判定"（域名解析到内网 IP）与"302 Location 提取"两条启发式（参照 `srun-autologin`）。
- 验收：双网卡环境下指定网卡后，请求源 IP 与所选网卡一致（用 `utils/mock_portal.py` 断言来源）；
  在未配置的门户上 `discover` 能靠 DNS 劫持判定出地址。

## 4. 目标设计与用户旅程

### 4.1 四层架构（在现有模块上长，不重写）

```
┌─ 交互层 ───────────────────────────────────────────────┐
│ Web 控制台（PWA，手机可加到主屏幕 · 扫码配对）          │
│ CLI（cli/ 拆分后）· 浏览器扩展 · 桌面唯一菜单快捷方式    │
│ 手机快捷指令（URL scheme，一键关机/唤醒/检测）          │
├─ 能力层（actions.py 统一入口，UI 与 CLI 共用）──────────┤
│ 账号 · 检测 · 自启 · 电源（关机/重启/WOL/唤醒计划）     │
│ 体检修复（power prep）· 配对 · 远程接入向导 · 通知      │
├─ 守护层 ──────────────────────────────────────────────┤
│ monitor（探活/重连/退避）· lockfile 单实例 · 看护任务    │
│ 平台载体：计划任务 / systemd(system) / LaunchDaemon     │
├─ 协议层（已实测，冻结）────────────────────────────────┤
│ portal 识别 · SRUN 协议 · 规则 JSON · fixture 回放      │
└───────────────────────────────────────────────────────┘
```

### 4.2 三条关键设计决策

1. **"通电即跑"和"通电即开机"是两件事，必须分开承诺。**
   程序只能保证"有电且系统起来之后，网络一定被接回来"；"机器要不要起来"交给 BIOS 来电自启/智能插座/WOL。
   README 顶部用一张表把这两件事的责任边界写死，避免 issue 里反复解释。
2. **远程开机的三层降级，按"宿舍断电"的现实排序。**
   | 层 | 手段 | 适用 | 前置条件 |
   |---|---|---|---|
   | L1 | BIOS 来电自启 + 智能插座 | **断电场景首选**（用户原话：晚上宿舍断电） | 主板支持；插座在线（整体断电需 4G 插座） |
   | L2 | 常开跳板（树莓派/旧路由/旧手机/软路由）+ WOL | 机器有电但关机/睡眠 | 跳板与目标在同一二层 |
   | L3 | 同网段手机 WOL App / 路由器插件 | 临时应急 | 手机在同一局域网 |
   三层都写进控制台"电源"页，配可复制的命令与二维码。
3. **规则层只放数据，不放代码。**（已有决策，继续保持）——远程更新规则 = 更新 JSON，
   最坏情况是规则失效，不会变成任意代码执行。

### 4.3 目标用户旅程（陌生同学视角）

**首次配置（目标 ≤5 分钟、3 步）**

1. 一行命令安装（或下载对应平台单文件 / `docker compose up -d`）；
2. 浏览器自动打开向导 → 自动发现门户 → 填账号密码 → "立即测试"通过；
3. 点"**一键准备远程使用**"：能自动做的全做（注册自启、电源体检、生成配对二维码、
   生成手机快捷指令链接），需要人工的列成带勾选框的清单（BIOS 来电自启、买智能插座、装 Tailscale/RustDesk）。

**日常（无需任何操作）**

通电 → BIOS 自启 → （可选自动登录）→ 服务随开机拉起 → 探活 → 自动认证 → 手机收到"已联网"通知。

**远程（手机 / 平板）**

扫一次码进控制台 → 加到主屏幕 → 之后从主屏幕或系统快捷指令直接"看状态 / 关机 / 唤醒 / 立即检测"。

### 4.4 明确不做（写进 README，挡掉无穷无尽的 issue）

802.1X / EAPoL、PPPoE 拨号、客户端强管控（MAC 绑定、专有加密协议）、绕过计费或共享上网、
给非本人设备做认证、任何"破解"性质的功能。

**验收**：`--help` 输出与拆分前逐行一致；覆盖率 ≥90%；故意提一个坏 PR 被必需检查拦住；
故意把 README 里某条命令改错，F6 的测试变红。

## 6. 新增 API 与数据模型

契约由真实路由表生成（`openapi.build(handler.routes.keys())`），**新增路由必须同步
`test_openapi.py` 里的一致性测试**，否则 CI 会红——这是已有的好机制，继续用。

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/pair` | 生成一次性配对码（返回 `code` / `url` / `expires_at`） |
| `POST` | `/api/pair/claim` | 用配对码换取正式会话 Cookie |
| `GET` | `/api/doctor/power` | 电源体检结果（数组：`item` / `status` / `detail` / `fixable`） |
| `POST` | `/api/doctor/power/fix` | 批量修复可自动化的项（需 `confirm`） |
| `GET` `POST` `DELETE` | `/api/wake-plans[/{id}]` | 唤醒计划 |
| `GET` `POST` | `/api/devices[/{id}/wake]` | WOL 设备清单与一键唤醒 |
| `GET` | `/api/access/guide` | 远程接入向导内容 + Tailscale 状态摘要 |
| `GET` `POST` | `/api/notify/channels`、`/api/notify/test` | 通知渠道与测试发送 |

数据结构（沿用现有 SQLite，`storage.py` 迁移用 `user_version`）：

```sql
-- 唤醒计划
CREATE TABLE wake_plans (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL, mac TEXT NOT NULL,
  broadcast TEXT DEFAULT '255.255.255.255', port INTEGER DEFAULT 9,
  schedule TEXT NOT NULL,          -- 形如 "07:30" 或 "mon-fri 07:30"
  enabled INTEGER DEFAULT 1, last_run_at TEXT
);
-- 唤醒设备清单
CREATE TABLE devices (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL, mac TEXT NOT NULL,
  note TEXT, created_at TEXT NOT NULL
);
-- 配对码：只存哈希，不存明文
CREATE TABLE pair_codes (
  code_hash TEXT PRIMARY KEY, created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL, used_at TEXT, user_agent TEXT
);
-- 体检留档：便于回答"上次修复了什么"
CREATE TABLE power_audit (
  id INTEGER PRIMARY KEY, created_at TEXT NOT NULL,
  item TEXT NOT NULL, result TEXT NOT NULL, detail TEXT
);
```

**安全要求**：配对码只存哈希、默认 5 分钟过期、单次使用、失败 3 次锁定并记事件；
`/api/doctor/power/fix` 与电源动作一样要求同源 + 会话 + `confirm`。

## 8. 需要用户本人做的事（非代码）

1. **一次 UAC 提权**：账户不是管理员，"无需登录即运行"的计划任务注册必须由本人授权
   （桌面已有自我提权快捷方式）。注册时需要一个 Windows 登录口令——
   如果平时用的登录口令比较弱，**建议先换成强密码再注册**。
2. **BIOS 设置来电自启**：重启进 BIOS → `Restore AC Power Loss` / `After Power Loss` /
   `AC Power Recovery` → 设为 **Power On**。这是"宿舍断电后自动开机"的唯一软件不可替代的前提。
3. **智能插座**（可选但推荐）：普通 Wi-Fi 插座在宿舍整体断电时也没网，
   若要"任何情况下都能远程上电"，需要自带 4G/SIM 的插座。
4. **Tailscale 账号**：电脑与手机都装（免费档足够），这是"任何网络下都能连回宿舍台式机"最省事的方案；
   远程桌面桌面端推荐 RustDesk（国产网络友好）。
5. **GitHub 付费开关**：`secret_scanning_non_provider_patterns` 与
   `secret_scanning_validity_checks` 属于 GitHub Secret Protection（付费），
   免费档拿不到（本次已实测：API 返回 200 但状态仍为 disabled）。
   不升级也能兜住——push protection 已开 + 自研扫描进 CI + F5 的本地预提交钩子。
6. **决定支持承诺范围**：macOS/Linux 单文件要不要算"官方支持"（影响 CI 矩阵与 issue 模板措辞）。

## 9. 风险与回退

| 风险 | 影响 | 对策 |
|---|---|---|
| 平台矩阵扩大 | CI 时间与失败面变大 | 单文件构建只在 tag 触发；非 tag 只跑测试与扫描 |
| macOS 产物未签名 | 用户看到"无法验证开发者" | README 写清右键打开步骤，不承诺公证（notarization 需付费账号） |
| 计划任务需管理员 | 本机无法全自动验证 | 设计成"提权可选"，未提权时降级到登录自启并在 UI 明示差异 |
| 多架构镜像构建慢 | CI 分钟数消耗 | 只在 tag 构建并加缓存 |
| 规则投稿质量参差 | 错误规则导致误判 | `profiles --validate` + fixture 回归门禁 |
| 文档命令漂移 | 用户照抄报错 | F6 的 README 命令冒烟测试 |
| 改动过大导致回归 | 影响正在用的用户 | 每阶段独立提交、独立验收；协议层冻结；`/api/v1` 保持兼容 |
