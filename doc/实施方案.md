## 1. 定位、边界与成功标准

### 1.1 一句话定位

**Web 门户认证型校园网的自动重连程序：开机即认证、掉线自恢复、多平台通用、可无人值守。**

### 1.2 能力边界（写进 README，避免无穷 issue）

| 做 | 不做 |
|---|---|
| Web 门户认证（SRUN / Dr.COM / ePortal / H3C / 华为 / 锐捷 / CAS 等） | 802.1X / EAPoL（需驱动、证书、管理员权限） |
| 断线检测、自动重登、会话复核 | PPPoE 拨号（需 root 或系统拨号配置） |
| 三平台用户级自启动 | 客户端强管控网络（MAC 绑定、专有协议） |
| 凭据本机加密保存 | 任何绕过计费的用法 |

### 1.3 成功标准（可验收）

1. 机器重启后**无需任何人登录**，认证自动完成，`/api/health` 可用。
2. 拔网线/切掉线后，程序在 1~2 个检测周期内自动恢复，且不产生假成功。
3. 新增一所学校 = 加一条声明式规则，不改 Python 代码。
4. 普通学生不需要装 Python 就能用（单文件分发）。
5. 连续认证失败时，用户能在异地收到通知。

## 2. 目标架构

### 2.1 分层

```
客户端层    Web 控制台(现有) / CLI / 浏览器扩展(瘦身) / 未来移动端
                    ↓  HTTP API（契约化、/api/v1）
接口层      routes_* + 同源校验 + 令牌认证 + 统一错误码
                    ↓
调度层      启动状态机 → 周期探活 → 退避重试 → 暂停时段
                    ↓
判定层      多目标连通性探活  +  门户会话复核（两层判定）
                    ↓
认证层      srun / http / browser / manual  ←  规则包(profile) 驱动
                    ↓
存储层      SQLite（迁移框架 / 状态字段拆分 / 事件裁剪）
                    ↓
运行层      单实例锁 + 日志落盘 + 自启动载体(计划任务/systemd/LaunchAgent)
                    ↓
分发层      单文件 EXE / 单二进制 + 一键启动 + 更新
```

### 2.2 五条设计原则

1. **纯 HTTP 优先、浏览器兜底**：SRUN 这类可纯 HTTP 复现的走快路径，
   JS 渲染/验证码场景才用 Playwright；同校开源项目的 selenium 方案作者自己都标注
   「不建议使用」。
2. **声明式规则，规则里没有代码**：规则包若允许执行代码，远端更新就等于任意代码执行。
3. **凭据 fail-closed**：POSIX 上令牌/密钥文件权限收不紧就报错停止，而不是降级放行。
4. **状态与事实分离**：连通性结论、最近成功连通时间、最近检测时间分别存，而不是一个字段兼三职。
5. **一切无人值守都要可观测**：日志落盘 + 失败通知，否则「为什么没连上」永远查不清。

### 2.3 现状与缺口（改动量评估）

| 模块 | 现状 | 缺口 | 改动量 |
|---|---|---|---|
| 自启动 | 三平台载体已实现；Windows 走启动文件夹（登录后语义） | 计划任务/服务模式（不登录也跑）；WSL/无桌面环境静默失效 | 中 |
| 单实例 | `lockfile.SingleInstance` 已实现且有测试 | **入口未调用**，双跑会抢同一份 SQLite | 小 |
| 存储 | SQLite + 事件裁剪 | 无迁移机制；状态字段过载 | 中 |
| 探活 | 单 canary；跳转上限已加（MAX_REDIRECTS=5） | 多目标、不可缓存、分层判定 | 小 |
| 认证 | http/srun/browser/manual 四模式；SRUN 已实测本校 | 规则化 profile；浏览器自学习 | 大 |
| 门户发现 | 7 类厂商指纹散在代码里 | 规则包 + 脱敏 fixture 回放 | 大 |
| 接口 | 25 条路由，写接口已有同源校验 | 无契约、无版本前缀、无统一错误码 | 中 |
| 日志 | stdout + 自启动重定向（块缓冲） | 文件日志按天保留、flush | 小 |
| 分发 | zip 分发包 + Actions | 单文件 EXE/二进制、一键脚本 | 中 |
| 扩展 | MV3，内含第二套登录实现 | 瘦身为「探活 + 通知 + 打开门户」 | 中 |
| 测试 | 647 passed / 5 skipped，覆盖率 89%（较早提交测得） | auth/crypto 低覆盖；macOS 未进 CI 矩阵 | 中 |

## 3. 模块设计

### 3.1 规则层（新增，最高优先级）

**进展（2026-10-12）**：规则层第一片已落地——`profiles.py` + `profiles/*.json`
（9 条内置规则，文件名数字前缀即匹配优先级），`discovery.identify_vendor` 改为调用
规则层，旧的三张厂商表变成派生视图以保持兼容；新增 `run.py profiles [--validate]`。
规则层的成功/失败标志已接入 `portal.classify_response`（命中规则时优先用规则里的
标志判断，未命中才走原有启发式）；脱敏 fixture 的采集与离线回放也已落地
（`fixtures.py` + `run.py portal-report [--from-file|--replay]`）。
字段候选也接进了登录路径：`pick_login_form(forms, profile)` 会优先挑含规则字段候选的
表单（页面里同时有搜索框和登录框时，启发式会挑错，规则给的名字更可靠），
`http_login` 在识别不到字段时回落到规则候选。投稿的 fixture 有了固定去处
`tests/fixtures/`（含一个示例夹具 + 回放测试）。
仍然待做：`login_mode` 的**模式分派**仍由账号字段驱动（规则只负责给建议）。

**目标**：把「一所学校 = 一段代码」变成「一所学校 = 一条规则」。

```yaml
id: srun
version: 1
name: 深澜 SRUN
match:
  url_contains: [srun_portal, srun_portal_pc, get_challenge]
  body_contains: [srbx1, srun_bx1]
auth:
  mode: srun                  # srun | http | browser | manual
  password_mode: plain
form:                         # mode=http 时使用
  username_field: [DDDDD, username, user]
  password_field: [upass, password]
  extra_hidden: [user_ip, user_mac, 0MKKey]
verify:
  success_contains: [login_ok, e0000]
  failure_contains: [result:0, sign_error]
```

要点：

- 内置规则与用户目录规则合并，用户规则优先；两者都带版本号。
- 现有 `discovery.VENDOR_SIGNATURES` / `VENDOR_LOGIN_MODES` / `VENDOR_PASSWORD_MODES`
  三张表和 `portal` 里的模式分支一起迁进来。
- 规则加载做 JSON Schema 校验；**不支持任何可执行表达式**。
- 验收：删掉代码里的厂商分支后，现有测试全绿；新增一条规则即可让新学校的 fixture 通过。

### 3.2 判定层（多目标探活）

- 探活目标从单值改为有序列表，任一放行即算联通；请求带 `Cache-Control: no-cache`，
  避免 CDN 缓存造成假在线（参考 `Georgeupup/szu-network-guardian` 的双请求复核）。
- 保留两层判定：先探活，探活失败再查门户会话；会话存在但连通未确认时写
  `STATE_UNKNOWN`，不算掉线、不触发重登。
- 验收：屏蔽单个目标后状态仍为在线；两个目标都被拦时状态为「在线未确认」，事件日志可解释。

### 3.3 认证层

- 快路径：`http` / `srun` 纯 HTTP 实现（本校已跑通）。
- 兜底：`browser`（Playwright），选择器按「字段名 → placeholder → 标签文案 → 可填写性」依次猜测。
- **自学习**：浏览器模式登录成功后，把成功的选择器组合落成一条本地 profile，
  下次直接走 HTTP 快路径。
- 验收：模拟门户上用错误选择器走一次 browser 登录成功后，第二次登录走纯 HTTP 且不再启动浏览器。

### 3.4 调度层

- **启动状态机**：等待网卡就绪 → 确认网络身份（SSID/网关） → 探活 → 认证 → 复检 → 退避。
  现在的 180 秒热身窗口是它的简化版。
- **暂停时段**：配置夜间时段内不重连（宿舍断电/熄灯场景）。
- 账号级并发：小线程池 + 每账号自己的下次检测时间，避免慢账号拖住快账号；
  撞锁时明确返回 `stale: true`，不要静默给旧结果。

### 3.5 存储层

**迁移框架**（当前完全没有，属于必须补的债）：

```python
SCHEMA_VERSION = 2

def migrate(conn):                     # 启动时执行，幂等
    version = conn.execute("PRAGMA user_version").fetchone()[0]
    for target, steps in MIGRATIONS:   # [(1, [sql...]), (2, [sql...])]
        if version < target:
            for sql in steps:
                conn.execute(sql)
            conn.execute(f"PRAGMA user_version = {target}")
```

**状态字段拆分**：`last_state`（online/offline/failed/unknown）+ `last_ok_at` +
`last_checked_at`，前端据此展示「多久前在线过」。

验收：用上一版 schema 建库 → 启动程序 → 列齐全且数据不丢；`pytest` 新增该用例。

### 3.6 接口层

- 写接口的同源校验已就绪（`require_same_origin` 覆盖 POST/PUT/DELETE/PATCH）。
- 补：`/api/v1` 前缀、OpenAPI 3.1 契约（可由实现生成，也可反哺测试）、统一错误码
  （`code` + `message`），把当前 25 条路由的请求/响应落成文档。

### 3.7 运行层

- **单实例**：`serve()` 启动即 `SingleInstance.acquire()`，失败时用 `holder_pid()`
  打印「已有实例 PID xxx 在运行」并退出（区分退出码）。
- **日志**：`logging` + 按天 FileHandler，保留 N 天；stdout 仅保留人类可读摘要。
- **自启动载体**：
  - Windows：计划任务（开机触发 + 不管用户是否登录 + 指定本人账户，不可用 SYSTEM，
    否则 DPAPI 解不开）；保留启动文件夹作为「登录后」模式的备选。
  - Linux：systemd user（有 systemctl）→ XDG autostart 退化；**无桌面/无 systemd 时
    status 必须报「不会生效」而不是已开启**。
  - macOS：LaunchAgent。
  - WSL 识别（`/proc/version` 含 microsoft）→ 明确提示不支持，不静默退化。

### 3.8 分发层

- PyInstaller 单文件 EXE（Windows）+ PyInstaller/单二进制（Linux/macOS），Actions 自动构建。
- 一键启动脚本：自动检测/安装依赖；更新脚本：`git pull` + 依赖同步。
- 验收：在一台全新 Windows（无 Python）上双击即用。

### 3.9 客户端

- Web 控制台：补「认证失败原因分类」（密码错/验证码/字段识别失败）与凭据导出/导入入口。
- 浏览器扩展：删掉第二套登录实现，改为「探活 + 通知 + 打开门户」，登录统一走本地服务。

**进展（2026-10-12）**：扩展已加「优先交给本地服务」——检测到
`http://127.0.0.1:2268/api/health` 可用就把这一轮交给 Python 版处理，连不上
静默回落到自带实现（并加了两个用例：可用时走服务、不可用时正常回落）。
这消掉了「两套实现漂移」的主要风险；自带 fetch 登录暂未删除——没装 Python 的用户
仍然需要它，删掉会直接损失一类用户。控制台的失败原因分类与凭据导入/导出入口仍待做。

## 4. 数据与安全

### 4.1 凭据

| 平台 | 存储 | 影响 |
|---|---|---|
| Windows | DPAPI（`v3.dpapi.`，绑定当前用户） | 换机/重装后解不开，必须重录 → 需要导出/导入 |
| 其它 | `~/.campusnet_obf.key` + HMAC 流加密（`v2.`） | 文件丢失即不可恢复 → 必须纳入备份 |

- 令牌文件 POSIX 上强制 0600，收不紧就 fail-closed（已实现）；报错需带路径与补救办法。
- 新增 `cred export/import`：导出口令二次加密，解决迁移问题。

### 4.2 网络暴露

- 默认绑定 `127.0.0.1`；绑定非回环时启用令牌认证。
- 远程访问只走隧道（Tailscale/ZeroTier/frp），**不做公网端口映射**（RDP 爆破是勒索主入口）。
- 校园网合规：私搭隧道、长期占用带宽可能违反学校网络管理办法，需自担。

### 4.3 规则库信任

规则包只允许声明式数据；远端更新走签名或至少「禁止代码」的硬校验，否则等于任意代码执行。

## 6. 无人值守部署（宿舍台式机场景）

### 6.1 硬件与固件

1. BIOS/UEFI：**断电恢复 = Power On**（免费，覆盖宿舍夜间断电；来电即开机）。
2. 需要「关机后再开」时，用带外手段：
   - 同二层常开小设备（树莓派/旧路由）发 WOL —— 可靠，但它自己也跑本程序维持在线；
   - 智能插座需注意**插座自己也要联网**，而校园网要网页认证、插座没浏览器，
     因此要么用 4G 版继电器，要么挂在已过认证的路由器下。
3. Windows 关闭「快速启动」、网卡勾选「允许此设备唤醒计算机」。

### 6.2 软件链路

```
来电/唤醒 → 系统启动 → 计划任务拉起 campusnet（无需登录）→ 自动认证
        → Tailscale 上线 → 手机/家里 RDP 或 RustDesk 接入
```

- 自启动载体：`python utils/run.py bootstart install --mode task`。
  注册的是「开机触发、无论是否登录都运行」的计划任务，密码只在注册时从 stdin
  交给任务计划程序保存；默认的 `auto` 模式是「登录后」语义，达不到上面的链路。
- 关机侧：控制台「设置」页的**远程关机 / 远程重启**按钮（对应
  `POST /api/power/{off|reboot}`，必须带 `confirm`），命令行等价
  `python utils/run.py power off|reboot`。开机侧只能靠 BIOS 上电自启 + 智能插座、
  WOL（`power wake --mac`，需同二层设备执行）或带外继电器。
- 开机信息：`GET /api/power/info` 返回网卡 MAC（已连接优先）、唤醒命令与三条硬件
  路线说明，控制台「怎么远程开机」按钮直接展示；CLI 用 `run.py access` 也能看到。
- **已知限制**：注册「开机触发、无需登录」的计划任务需要管理员权限——实测非管理员
  账户下 `schtasks /Create ... /RP` 与 `Register-ScheduledTask -User -Password`
  都会被系统拒绝（Access is denied）。因此桌面快捷方式里单独生成了一个会弹 UAC 的
  「注册开机自启-无需登录(需管理员)」；不满足条件时程序会明确提示这一点，而不是
  留下一个起不来的启动项。
- 远程桌面：专业版用 RDP（仅从 Tailscale 网段访问），家庭版用 RustDesk/ToDesk。
- 隧道：Tailscale 服务模式开机自启；UDP 被挡时走 443 中继。
- 兜底：认证失败要让隧道之外的通道也能通知到你（P1 的通知出口）。

## 8. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单账号多设备互踢 | 远程登录取代宿舍机，或反之 | 会话占用时可选「不抢回」开关；或为设备单独办账号 |
| DPAPI 绑定用户/机器 | 换机重装后凭据失效 | P1 的 cred export/import |
| 规则包含代码 | 远端更新 = 任意代码执行 | 只允许声明式数据 + Schema 校验 |
| 自启动语义误解 | 以为「已开启」实则永不生效 | status 区分「载体在本机是否会生效」；WSL 明确不支持 |
| 校园网管理办法 | 被断网或约谈 | 只做自用认证，不对外提供服务，不搭公网映射 |
| 探活目标被拦 | 大量「在线未确认」 | 多目标 + 会话复核双层判定 |
